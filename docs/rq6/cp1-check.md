# CP1 점검: 하네스·오라클 검증 완료 여부 (AI 초안 v0.1)

- 작성일: 2026-11-01 (KST) · 작성: Claude(AI 조수) · 사람의 검토 전 · **통과 선언이 아님**
- CP1은 문서 02 §6.2 단계 B의 체크포인트 "하네스·오라클 검증 완료"다. 이 문서는 기준마다 저장소의 증거를 대응시킨 **점검표**이고, CP1을 통과로 볼지는 사람이 정한다.
- 기준의 출처: 문서 02 §4의 SI-2 완료 기준(입력 형식 정의, 소규모 전수 일치, 크기·시간 한계표, 단위 테스트)과 교차 검증 항목, SI-4 완료 기준(RQ6의 기준 구현으로 처음부터 끝까지 검증: 같은 입력은 같은 출력, 재실행 시 요약 통계가 사전에 정한 허용 범위 안), §5.1 WP6.2의 완료 기준(오라클과 소규모 전수 일치), `prereg/README.md` §4의 SP-5(구현 무결성 관문).
- 상태 표기: **증거 있음**(기준에 대응하는 결과 파일이 있다. 사람의 검토는 별도), **부분**, **안 함**, **사람 결정 대기**. '증거 있음'은 AI가 증거를 대응시켰다는 뜻이다.
- 파일럿(`docs/rq6/pilot.md`)이 만든 증거를 일부 쓴다. 파일럿 자료는 본 분석에 쓰지 않으며 여기서도 도구 점검(O1 대조, 재현성)에만 쓴다.

## 5. 끝에서 끝까지 재현 (SI-4 완료 기준)에 대한 파일럿 증거

`experiments/pilot/R.jsonl` (프로토콜 `docs/rq6/pilot.md` §3, 결과 §7.8).

- 같은 마스터 시드로 기준 구현 둘을 두 번 실행(`runner.execute`): 계수 기록 28개의 키 집합이 같고 서로 다른 기록 0개. 기준 구현의 판정과 입력의 표지가 다른 기록 0개.
- 열두 정책의 계수 기록 168개: 같은 프로세스에서 두 번 실행해도, 해시 시드가 다른 별도 프로세스에서 실행해도 완전히 같다.
- 시간: 호출당 중앙값이 0.1 ms 이상인 (정책, 셀) 쌍 6개가 모두 사전에 정한 허용 범위 [0.85, 1.18] 안(재실행/첫 실행 비 0.990–1.014).

한계: 시간 쌍이 6개뿐이고 두 실행이 연달아 이루어졌다(같은 시간대). 먼 시각의 재실행이나 다른 환경에서의 재현은 보지 않았다. 허용 범위는 AI의 제안이며 SI-4가 요구한 '사전에 정한 허용 범위'를 사람이 확정해야 한다.

## 6. CP1 판단에 필요한 사람의 결정

1. 단위 테스트의 형식: 점검 스크립트(`check_*.py`)로 SI-2의 '단위 테스트' 기준을 채운 것으로 보는가?
2. 독립 교차 검증(Alloy 6 또는 TLA+, F8 동치)을 CP1 전에 요구하는가, 아니면 동결 전 다른 시점으로 미루는가?
3. O3의 크기·시간 한계표를 CP1에 요구하는가? (RQ6은 O1만 쓴다)
4. 환경 고정(문서 06 Q3, R-7)의 답. 답이 없으면 현재 환경의 절대 시간은 참고용이고 K2(비교 횟수)를 1차 근거로 삼는다는 읽기를 유지한다.
5. 파일럿 R의 허용 범위와 재현 범위가 SI-4 완료 기준에 충분한가(O6-10 나).
6. 교재 출처(R-4)와 EWD623 원문 확인(R-5)은 사람이 자료를 주어야 한다.

## 7. AI의 한 줄 평가

코드와 점검 쪽에서는 SI-2 O1, SI-4, WP6.2의 기준마다 대응하는 증거가 있다. 남은 것은 환경 고정, 독립 교차 검증, O3의 크기·시간표, 원문 대조, 그리고 사람의 검토다. 이 문서는 CP1을 통과시키지 않는다. 통과 여부는 사람이 §6의 항목을 정한 뒤 판단한다.
