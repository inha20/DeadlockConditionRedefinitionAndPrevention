- 이 표는 **새로 읽어서 만든 것이 아니다.** 이미 대장에 기록된 서술을 '모델의 가정, 표현할 수 있는 사례, 증명한 것'의 열로 다시 배열했다. 원문을 다시 열지 않았고 대장에 없는 사실을 더하지 않았다.

## 0. 읽는 법

- 수준은 문서 01 §0.1을 따른다. A−는 열람 도구가 돌려준 본문 요약, B는 초록이나 목록 항목, C는 2차 서술이다. 수치와 문장은 원문 재확인 전에는 논증의 전제로 쓰지 않는다.
- 칸의 표기: **보임**은 요약이 그 사례를 다룬다고 쓴 것, **가정으로 제외**는 정리의 가정이 그 사례를 분석 밖에 둔 것, **요약에 없음**은 열람한 요약에 서술이 없다는 뜻이다. **요약에 없음은 '없음'이 아니다.** 본문에 있을 수 있다.
- 이 표는 G4 판정(문서 05 §6.4)을 바꾸지 않는다. 판정은 '동일/부분/없음'이고 이 표는 WP5.4에서 정의와 정리를 쓸 때 무엇과 맞춰 볼지의 목록이다.

## 2. 대상별 상세

### 2.1 S35 Archerfish (대장 C-SUR-105, 171–173)

| 열 | 내용 |
|---|---|
| 모델의 가정 | 락 객체를 정점으로 하고 스레드·ISR 실행 안에서 한 락을 쥔 채 다른 락을 얻는 일반 간선과, ISR이 락 보유 코드를 선점해 다른 락을 얻는 인터럽트 간선을 둔다. 스레드 전환은 전환된 스레드가 다시 실행되어 락을 풀 수 있으므로 이 의존을 만들지 못한다고 설명한다. 간접 호출은 '표준 포인터 분석'이라고만 서술한다 |
| 표현할 수 있는 사례 | 인터럽트 재진입 자기 교착: 보임(비형식 사례). 사용 상태: 요약에 없음. 중첩 인터럽트: 요약에 없음 |
| 증명한 것 | 없음. 인터럽트 간선이 하나 이상 든 순환(ILC)을 표준 순환 열거로 찾고 happens-before와 경로 실현성으로 검증하며, ILC가 반드시 실제 교착은 아니라고 쓴다. 인터럽트와 교착의 형식 모델은 인용하지 않는다 |
| 이 연구와의 접점 | 5f(탐지 기법)는 기여로 주장하지 않는다. 5a(이웃), 5d(비형식 서술), 5g(도구 수준), 5h(이웃). 코드북 V12(의존의 종류)가 이 구분을 옮긴 것이다 |
| 한계 | 열람 도구 요약. 초록만 읽은 쪽(C-SUR-105)은 B. 실측 수치(Linux v6.4에서 ILC 353개 중 151개 보고, 진짜 76, 거짓 75)는 논증에 쓰지 않는다. 인터럽트 기반 교착의 첫 정적 접근이라는 저자의 서술은 이 저장소에서 검증하지 않았다 |

### 2.2 M58 Suenaga–Kobayashi (C-SUR-106, 183)

| 열 | 내용 |
|---|---|
| 모델의 가정 | 스레드와 인터럽트 기본 연산이 있는 병행 계산. 락마다 수준을 주고, 인터럽트가 켜진 구간을 포함해 수준이 증가하는 순서로 획득하는지 타입으로 검사한다. 수준의 하한과 상한을 모두 추적해야 한다고 쓴다. 비동기 예외는 중단된 문맥이 재개되지 않는다는 점에서 인터럽트와 구분한다 |
| 표현할 수 있는 사례 | 인터럽트 재진입 자기 교착: 요약에 없음. 사용 상태: 인터럽트가 켜진 구간이 타입에 있음(대응 대조 안 함). 중첩 인터럽트: 요약에 없음 |
| 증명한 것 | 정리 1: 건전성(타입이 맞으면 교착 없음). 완전성·필요성 결과 없음. 복잡도나 결정 가능성 결과 없음. 증명과 추론 알고리즘은 완전판으로 미룬다 |
| 이 연구와의 접점 | 5a, 5b, 5d(이웃). 락 수준 규칙 부분은 5b와 같은 결과일 수 있어 그렇다면 5b 중 그 부분은 '동일'에 가까워진다(문서 05 §6.4). 관련 연구 서술: 인터럽트를 다룬 선행 해석은 동시성이 없어 교착 분석에 쓸 수 없고, 교착 자유 분석은 인터럽트를 다루지 않는다고 쓴다 |
| 한계 | A−(본문 요약). 게재처는 본문에 없고 파일명이 esop2007이며 목록 항목으로 확인했다(B). 계산 모델 본문은 일부만 보았다. 정의와 정리를 이 저장소의 모델 위에서 대조하지 못했다 |

## 5. WP5.4에서 맞춰 볼 질문 (주장이 아님)

아래는 정의와 정리를 쓸 때 이웃 문헌과 어디서 겹치는지 확인하기 위한 질문이다. 답을 이 문서에서 주장하지 않는다.

1. M58의 '수준이 증가하는 순서 + 인터럽트가 켜진 구간' 규율을, 비자율 요청과 문맥 종류를 가진 확장 모델 위의 충분조건(S3)으로 옮기면 같은 진술인가? 같으면 5b 중 그 부분은 '동일'에 가깝다.
2. M112의 가정 목록(단일 프로세서, 정적 천장, 이진 세마포어, 올바른 중첩, 종료 전 해제, 자기 교착 없음, 인터럽트 없음) 가운데 확장 모델에서 유지되는 것과 버려야 하는 것은 무엇인가?
3. S37의 '처리기용 보호 프로시저의 천장은 인터럽트 우선순위 범위' 규칙을 확장 모델의 불변식으로 쓸 수 있는가?
4. S35의 ILC는 '반드시 실제 교착은 아니다'라고 서술된다. 실제 인터럽트 교착이 항상 ILC를 포함하는가(필요조건)는 S35가 서술하지 않는다. 확장 모델에서 그 진술을 쓸 수 있는가?
5. lockdep의 사용 상태 규칙이 확장 모델의 어떤 진술의 특수한 경우인가(5e)? 사용 상태 규칙은 문맥별로 켜진 채 획득된 이력을 요구하는데, 모델의 상태에서는 그 이력을 어떻게 표현하는가?

## 6. 한계와 빈자리

- 칸의 대부분이 열람 도구 요약(A−)이나 초록(B)에서 왔다. 정방향 인용 추적을 하지 못했다(문서 05 §6.3).
- '요약에 없음'인 칸(S35의 사용 상태·중첩 인터럽트, M58의 자기 교착·중첩 인터럽트, S37의 중첩 인터럽트)은 원문을 읽으면 채워질 수 있다.
- 읽지 못한 원문(DLOS 본문, Diaz–Touili 두 편, DEPT 패치 본문, Breuer 외 2004, ISSTA 2023 연구, lockdep 소스)은 이 표의 대상이 아니지만 5a, 5b, 5f와 겹칠 수 있다. 이 가운데 DLOS, Diaz–Touili, Breuer, ISSTA 2023 연구는 열린 항목 O5-6(사람이 PDF를 제공)에 있고 DEPT 패치 본문과 lockdep 소스는 아직 항목이 없다.
- 이 표는 사실의 재배열이므로 새로움을 주장하지 않는다.
