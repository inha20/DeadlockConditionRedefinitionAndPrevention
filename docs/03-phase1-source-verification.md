## 1. 방법과 한계

- 확인일: 2026-10-29. 도구는 웹 검색(미국 대상 검색), 페이지 열람 도구, 작업공간 셸이다. 웹 검색은 약 18회, 페이지 열람은 실패·거부를 포함해 약 30회 시도했다.
- 페이지 열람 도구는 본문을 요약해서 돌려준다. 그래서 이 도구로 읽은 내용은 본문 직접 열람이 아니라 발췌로 보고 A−로 표기한다. 코드로 직접 계산한 값(E2 데이터셋)만 A로 표기한다. 숫자와 정리 번호는 논증의 전제로 쓰기 전에 원문으로 다시 확인한다.
- 접근이 거부된 곳: 홀트 논문 검색에 걸린 문서 공유 사이트의 문서(제목 'September', 홀트 논문이 실린 1972년 9월호의 사본일 가능성이 있으나 내용은 보지 못함)는 자동 권한 검토가 "접근이 제한된 자료의 복사본"이라는 이유로 열람을 거부했다. 이 거부를 다른 경로로 우회하지 않았다.
- 판독 한계: Bak 1984(M23)의 PDF는 OCR이 손상돼 수식 일부를 읽을 수 없다.
- 부재 증명이 아님: "찾지 못했다"는 이번 검색 범위에서 못 찾았다는 뜻이다. 검색 도구가 미국 대상이고 Scholar, AFP, Mathlib 색인, KCI, RISS, DBpia를 직접 조회하지 못했다.

### 3.4 해석과 한계

1. **서술과 열 값의 관계가 풀리지 않았다.** 논문은 인터럽트에 의한 재진입을 이중 락의 또 다른 주요 원인이라고 쓰고(§4.2), 교착의 스레드 수를 셀 때 인터럽트 핸들러를 별도 스레드로 세지 않는다고 쓴다. 이 두 서술을 합치면 인터럽트 재진입 사례는 단일 스레드 교착 16건에 들어가야 한다. 그런데 데이터셋에서 이 16건의 인터럽트 의존 열은 true가 0건이다. 논문이 이 16건의 원인별 건수를 제시하지 않아서 어느 쪽이 맞는지 알 수 없다. 가능한 이유는 (a) 열의 정의가 "관련 코드 영역이 인터럽트 처리로만 도달 가능"일 것을 요구해(§3.1) 같은 코드가 시스템 호출로도 도달되면 false가 되는 것, (b) 이중 락 버그의 범위가 단일 스레드 교착의 범위와 다른 것, (c) 인터럽트 재진입 사례가 실제로는 적은 것이다. 어느 것도 확인하지 못했다.
2. 따라서 "커널 교착 중 상당수가 인터럽트 재진입에서 온다"는 문서 01의 원래 서술은 근거로 쓸 수 없다. 근거가 있는 것은 "교착의 32.7%가 단일 스레드로 발생하고, 논문이 든 원인은 함수 포인터 간접 호출과 인터럽트 재진입이다"까지다. 두 원인의 비중은 49건의 패치를 읽어 사례별로 코딩해야 안다(RQ5 WP5.2).
3. 열 이름은 '실행 문맥 수'인데 논문의 통계는 스레드 수를 센다. 논문은 이 통계에서 '실행 문맥'을 따로 정의하지 않는다. 숫자가 일치하므로 같은 값일 가능성이 높지만 확인하지는 못했다.
4. 데이터셋의 표기가 일관되지 않다. `rwsem`과 `rw_semaphore`가 섞여 있고 `wrong-chioce`라는 철자 오류가 있다. 재사용 전에 정리가 필요하다.
5. 수정된 버그만 포함한다(생존 편향). 키워드로 고른 표본이다(문서 01 §2.6).

## 7. 연구 설계에 미치는 영향

1. **RQ5**. 가설 H5를 둘로 나눈다. H5a는 자기 대기(한 프로세스가 이미 쥔 자원을 다시 요청, 길이 1 사이클)와 단일 스레드 이중 락이 조건 모델에서 어디에 놓이는가이다. H5b는 인터럽트 재진입이 비자율 요청으로 모델링되어야 하는가이다. 인터럽트 기여분이 확인되지 않았으므로 H5b에는 반증 조건을 추가한다: 49건의 코딩에서 인터럽트 재진입으로 판정한 단일 스레드 사례가 사전에 정한 최소 건수에 못 미치면 H5b를 폐기한다. 이 최소 건수는 사전 등록 때 정한다.
2. **RQ1과 SI-1**. 모델 사양에 두 가지를 넣는다. (a) 현재 상태의 교착과 안전성의 구분. M9가 '교착 없는 불안전 상태'라는 이름으로 이 구분을 형식화한다. (b) 자기 대기를 허용하는지를 모델 매개변수로 둔다. 코프만과 홀트 원문이 자기 대기를 어떻게 다루는지는 F1, F2를 받아야 확인할 수 있다.
3. **RQ2**. 제조 시스템 맥락에서 구조 조건 아래 다항 시간 클래스가 이미 알려져 있다(M9 §5). 그래서 G4에서 '부분'일 가능성이 높다. RQ2가 독자적이려면 OS의 구조 제한(락 중첩 깊이, 인터럽트 문맥)으로 클래스를 정의하는 부분에 한정해야 한다.
4. **RQ6**. 후보에 Bak 1984(보수적 판정 가능성)와 Shin·Choi 2012(모델 상이 가능성)를 추가했다. Bak의 보고처럼 안전 상태를 불안전으로 판정하는 방법은 정확성 시험(WP6.4)의 보수적/비보수적 분류와 RQ3 지표 M1의 필요를 보여주는 사례다.
5. **RQ1 WP1.1**. 교재 서술(순환 대기를 둘 이상의 프로세스의 사슬로)과 원문 정의의 대조가 정의 비교표의 핵심 항목이 된다. F1, F2 확보에 달려 있다.

## 8. G1 판정과 일정 재추정

- **판정: 조건부 통과.** 통과 조건(문서 02 §3)은 원문 대조를 마쳤거나 못 한 사유를 기록하는 것이다. 사유와 시도는 §2에 있다. 조건은 두 가지다. ① F1, F2, F3 칸은 원문을 받기 전까지 '원문 미확인'으로 표시한다. ② 근거 수준이 C 이하인 항목은 논증의 전제로 쓰지 않는다.
- **일정 재추정.** 계획은 사람 1인이 주 20시간으로 4주를 가정했다. 이번 작업은 AI가 한 번의 작업 세션에 수행했으므로 계획 소요와 직접 비교할 수 없다. 1.5배 규칙은 사람의 시간에 대한 것이므로 적용하지 않는다. 지금의 병목은 원문 확보와 사람의 검토다. 이후 단계는 원문이 도착하면 해당 칸을 승격하고, 도착하지 않아도 잠정 표시로 진행한다.
- **작업공간 확인 결과**(문서 02 §1.3에 반영): Python 3.13(numpy, scipy, pandas, matplotlib, networkx 있음, z3·hypothesis·pysat 없음), g++/gcc, Rust(cargo), Go, Node, Java 21, git 2.43, 코어 2개, 메모리 약 8GB. 공개 GitHub 저장소는 받을 수 있다. gh 인증 토큰이 유효하지 않아 작업공간에서 저장소를 만들 수 없다.
