### 0.1 확인 수준 표기

| 표기 | 의미 |

- 브리프 4장의 구분(예방/회피/탐지, 필요/충분/필요충분)을 유지한다. 뱅커 알고리즘은 회피다.

## 1. 1차 조사에서 확인된 것

### 1.1 코프만 네 조건의 논리적 지위: 문헌마다 서술이 다르다

1. 코프만 외(F1)는 이 조건들을 교착이 존재하기 위한 필요조건으로 정리하고, 예방을 그중 하나 이상을 처음부터 제거하는 설계로 소개한다. [A−] 원문 §2가 충분성을 어떻게 다루는지는 아직 읽지 못했다. [X]
2. 하벤더(F6)는 코프만보다 3년 앞서 실무 접근법 네 가지를 제시했다: 모든 과제가 같은 순서로 요청하기, 자원을 한꺼번에 요청하기, 추가 자원을 얻기 전에 보유 자원을 반납하고 함께 다시 요청하기, 요청이 거부되면 보유 자원을 쥔 채 기다리지 않고 대안 행동을 택하기. [A] 조건 목록 형태로 쓰지는 않았다.
   - 하벤더의 OS/360 사례는 정적 순서가 암묵적 획득 경로 때문에 뒤집힐 수 있음을 보여준다. 다음 작업 단계의 장치 할당 루틴이 이전 단계에서 얻은 영역(region) 안에서 실행되어, 의도한 순서가 실제로는 반대가 되는 문제다. [A] → 순서화 예방의 실무적 함정.
3. 탄넨바움은 네 조건 각각이 시스템이 가질 수도, 갖지 않을 수도 있는 정책과 관련된다고 쓴다. [B] (T2) 같은 계열로 보이는 교재 발췌 사본(저자·판본 미표시, T9)은 순환 대기를 둘 이상의 프로세스가 이루는 순환 사슬로 서술하고 네 조건이 모두 필요하다고만 쓰며 충분성은 다루지 않는다. [C] 이 서술이 길이 1의 자기 대기(한 프로세스가 이미 쥔 자원을 다시 요청)를 정의에서 제외하는지는 원문(F1, F2)으로 확인해야 한다. [X]
4. 필요/충분 표기가 일관되지 않다. 버지니아대 노트는 필요조건이지 충분조건이 아니라고 쓰고 [C], 켄트주립대 노트는 같은 내용에 필요충분이라는 제목을 붙이며 [C], 한 미국 특허 문서는 코프만을 필요충분으로 인용한다. [C] UC Davis ECS 150(1999) 핸드아웃(T10)은 제목과 도입에서 네 조건을 필요충분이라 쓰면서 본문에서는 필요성(조건 하나를 없애면 교착이 일어나지 않음)만 논증한다. [C] 레바인(F10)은 'deadlock'의 정의와 처리 방식이 문헌마다 일관되지 않다고 지적하고 죽은 상태(dead state)의 분류가 필요하다고 주장한다. [B] Fan 외(M70, 2021)의 초록은 고전 이론이 자원 순환 대기를 교착의 필요조건으로 본다고 서술하고, 자원 순환 대기가 교착 없이 일어나는 반례를 들어 이를 과도한 단순화라고 논한다. [B] 그런 반례는 순환 대기가 충분조건이 아님을 보이지 필요조건 서술을 반박하지는 않으므로 초록 문구가 무엇을 겨냥하는지 모호하다(해석). 본문(IEEE Access 9: 92586–92599)을 읽기 전에는 단서로만 두고 [X], 그 논문의 '자원 순환 대기'와 '사건 순환 대기'가 이 저장소의 순환 대기 정의와 같은지도 대조해야 한다.
5. 독립성은 새 주제가 아니다. 실버샤츠 교과서(사본)는 순환 대기가 점유-대기를 함의하므로 네 조건이 완전히 독립은 아니며, 그래도 각각을 따로 보는 것이 유용하다고 쓴다. [C] (T1)
6. 교육 자료 수준의 형식 증명이 있다. UIUC 코스북은 (교착 ⇒ 네 조건)과 (상호배제·점유-대기·비선점이 성립하는 시스템에서 자원 할당 그래프의 순환 ⇒ 교착)을 증명하고, 다중 인스턴스에서는 순환이 필요조건이지만 충분조건은 아니라고 설명한다. [C] (T4)

시사점: 조건의 논리적 지위를 먼저 고정해야 한다는 브리프의 문제의식은 문헌 상태와 맞는다. 다만 정책 수준 조건과 상태 수준 술어를 구분하는 관점은 일부 교과서·교육 자료가 이미 암묵적으로 쓰고(위 3, 6), 데이터베이스 잠금 정책 문헌은 잠금 정책과 교착 상태를 따로 정의한다(M65, A−. 문서 05 §4.4의 1a). 기여가 가능하다면 이 구분을 모델 매개변수화, 기계 검증, 예방 기법의 분류로 확장하는 데서 나온다. (가설, §4 RQ1. 이 확장에도 G4에서 부분적으로 겹치는 문헌이 확인되었다)

### 1.2 모델별 상태 판별 결과

C 항목은 홀트(F2) 원문과 대조하기 전에는 근거로 쓰지 않는다.

| 모델 | 결과 | 출처 | 수준 |
|---|---|---|---|
| 단일 단위 자원(expedient 상태) | 순환 ⟺ 교착 | T4, T6 | C |
| 다중 단위 자원 + 단일 단위 요청 | 매듭(knot) ⟺ 교착 | T6 | C |
| 일반 자원 그래프(재사용·소모성 자원) | 순환은 필요조건. expedient이면 매듭은 충분조건(필요조건은 아님). 현재 상태의 교착 여부는 그래프 축소가 완료되는지로 결정 | T6 | C |
| 최대 청구(claim) 그래프의 축소 가능성 | 교착 없음(안전)의 충분조건이며 필요조건은 아님 | T6 | C |
| AND 요청 모델 | 교착이려면 대기 그래프에 순환이 필요하고, 탐지 알고리즘은 순환이 있을 때 교착을 선언한다(Knapp §2.2). Knapp은 이를 단일 단위 자원으로 한정한다고 쓰지 않았다. 이 저장소의 모델(SM)에서는 모든 자원 용량이 1일 때 순환 ⇔ 교착이다(T2). 다중 단위 자원에서는 순환이 교착을 뜻하지 않는 반례가 있다(B4). v0.2의 '순환이 필요충분'은 강의 노트의 서술이었으며(T6, C) 단일 단위 자원에 한정해 읽어야 한다 | M14 §2.2, M62 §1.2–1.3, M63, 명세 T2·B4, T6 | A−, V, C |
| OR 요청 모델 | 순환은 충분하지 않다(순환 구성원 중 나가는 간선이 없는 프로세스가 진행할 수 있는 예). 교착은 매듭(knot)에 대응하고(Knapp은 Holt에 귀속) 매듭의 구성원은 교착 집합이다. 매듭 밖의 프로세스도 도달 가능한 프로세스가 모두 교착이면 교착이다. 매듭의 존재가 필요하다는 서술은 M17 §1 | M14 §2.3, M17 §1, M62 §1.3·§2.4, M63 | A− |
| AND-OR / P-out-of-Q 모델 | 순환은 필요하나 충분하지 않고, 매듭은 충분하나 필요하지 않다(M17 §1). Knapp §2.4는 AND-OR에 표준 그래프 구조가 없고 OR 검사를 반복하면 되지만 비효율이라고 쓰며, §2.5의 k-of-n은 정의가 부실해 순환·매듭 특성화를 주지 않는다고 쓴다. Knapp은 'P-out-of-Q'라는 용어를 쓰지 않는다. Barbosa(M63)는 x-out-of-y에 (y−x)-매듭이, AND-OR에 b-매듭이 필요충분이라고 서술한다(Thm 1.4, 1.5). M14, M17의 서술과 어긋나 보이나 정의가 다를 가능성이 크고 확인하지 못했다(문서 05 §4.4의 1c1) | M17 §1, M14 §2.4~2.5, M63 | A− |
| 재사용 자원 m종을 공유하는 n개 프로세스 시스템의 교착 자유성(가능한 요청은 즉시 허용하는 정책 기준) | 다항 시간 O(n³m) 테스트 존재(1977년판 초록). M21은 이 테스트가 Habermann 모델을 이분 그래프로 바꾸는 방식이라고 설명. Chen–Rem(M64)의 요약문은 expedient 할당 정책 아래 교착 자유성의 필요충분조건 두 개와 그 동치를 준다고 쓰며 한 조건은 Ibaraki–Kameda가 독립적으로 발견했다고 한다 | M1, M2, M21, M64 | B |
| 뱅커 모델의 안전 상태 | 순서 탐색으로 정확히 판정하며 증명이 있음 | F8 | A |
| 단일 단위 순차 자원 할당(Petri net) | 교착을 빈(unmarked) siphon으로 구조적으로 설명 | M11, M12 | B |

v0.3 주: AND, OR, AND-OR 세 행은 문서 04 §9의 정정 1·2에 따라 고쳤다(v0.2에서는 OR와 AND-OR를 한 행에 두었다). Knapp 서술(M14)은 열람 도구의 요약을 거친 A−이므로 본문과 다시 대조하기 전에는 논증의 전제로 쓰지 않는다. 'SM'은 이 저장소의 스냅샷 모델(`docs/spec/model-spec.md`)이고 V는 소규모 범위의 전수 검증이며 증명이 아니다. 모델별 현재 상태 판별의 더 자세한 지도는 문서 04 §4(a)에 있다.

v0.4 주: G4(문서 05 §4)에서 Herman–Chandy(M62)와 Barbosa(M63)를 읽어 위 AND, OR, AND-OR 행의 출처에 더했다. 두 문헌은 대기 그래프 수준(프로세스 정점만)에서 모델별 필요·충분·동치를 서술한다: AND는 순환, OR는 매듭이고 순환은 충분하지 않으며, x-out-of-y는 (y−x)-매듭, AND-OR은 b-매듭이 필요충분이고, 모든 모델에서 순환은 필요조건이다(M63. 열람 도구 요약, A−). 이 필요조건은 대기 그래프 수준의 서술이며 자원·용량 수준에서는 이 저장소의 SM 정리 T2n이 소규모 범위의 전수 검증으로 뒷받침한다(V). 다만 SM의 WFG·RAG 정의가 M63의 대기 그래프와 같은지는 대조하지 않았다(문서 04 §4(a)의 항목, 미처리). M14, M17의 서술과 M63의 b-매듭이 어긋나 보이는 것은 정의 차이일 가능성이 크나 확인하지 못했다. SM의 T2, T3, T5는 이 서술과 짝지어 '재현'으로 분류할 후보다(문서 05 §4.5의 2항). 소모성 자원 그래프(M77), 잠금 정책(M65), Petri net(M66, M68)의 결과는 문서 05 §4.2에 있고 이 표에는 옮기지 않았다.

### 1.4 실제 OS·런타임

- 교과서의 서지 노트(T1)는 OS가 보통 교착 예방 기능을 제공하지 않고 교착 없는 프로그램을 설계하는 일은 프로그래머 몫이라고 쓴다. 자원 순서화는 하벤더가 OS/360용으로 고안했다. FreeBSD의 witness 락 순서 검증기는 Baldwin(2002)으로 소개된다. [B, 후자는 D]
- 리눅스 lockdep(S1)은 락 클래스(인스턴스 수만 개가 하나의 클래스) 단위로 사용 상태와 클래스 간 의존성을 추적하고, 실제로는 아직 일어나지 않은 시나리오도 잠재적 역전으로 검증한다. 같은 클래스 안의 계층적 중첩은 어노테이션(nesting level)이 필요하며 잘못 매핑하면 오탐·미탐이 생길 수 있다고 문서가 경고한다. [A]
- 리눅스 ww_mutex(S2, S3): 락 클래스 단위로 wound-wait와 wait-die 중 하나를 고른다. 문서는 경쟁 트랜잭션이 적을 때 wound-wait를 권한다. 패치 설명의 마이크로벤치마크(4코어 x86_64): 4스레드에서 wound-wait는 롤백 약 100회·약 17초, wait-die는 약 15만 회·약 19초. 16스레드에서는 wound-wait 약 36만 회·약 109초, wait-die 약 45만 회·약 82초. 동료 심사를 거치지 않은 단일 환경 측정이다. [A−]
- 구글 Spanner 논문(OSDI 2012) §4.2.1은 읽기-쓰기 트랜잭션의 읽기에 wound-wait를 써서 교착을 피한다고 서술하고 Rosenkrantz 외(1978)를 인용한다(S17). [A−] S16도 같은 사실을 서술한다. [C]
- Abseil의 Mutex 디버그 모드는 락 획득 순서 DAG를 유지하고 순서가 어긋나면 잠재 교착을 보고하며, 증분 갱신에 Pearce–Kelly 알고리즘을 쓴다는 저자 블로그 글이 있다. [C] (S10) 소스 쪽 근거는 G4에서 확인했다. `graphcycles.cc`의 머리말이 Pearce–Kelly를 인용하고, `graphcycles.h`는 순환이 되는 간선의 삽입을 거부하고 그래프를 바꾸지 않는 증분 그래프이며, `mutex.h`는 교착 탐지가 디버그 빌드에서 전역으로 켜졌을 때만 acquired-before 그래프를 추적한다고 쓴다. [A−] (S27) 다만 `GraphCycles`가 `Mutex`의 그래프 구현이라는 연결은 헤더가 `absl/synchronization/internal`에 있다는 점과 S10(C)에 근거하며 `mutex.cc`는 읽지 않았다. 노드가 락 클래스인지 개별 뮤텍스인지도 헤더가 밝히지 않는다. Rust 크레이트 tracing-mutex도 Pearce–Kelly로 의존 그래프를 유지하고 순환이면 패닉하며, 릴리스에서도 쓸 수 있는 추적형 래퍼와 디버그 단언이 켜졌을 때만 추적하는 별칭을 둔다. [A−] (S28) 리눅스 lockdep의 설계 문서(S1)에는 위상 순서를 유지한다는 서술이 없다(문서 05 §2.2).

### RQ1. 조건의 층위 분리와 모델별 관계의 통합 형식화 (방향 A+B)

- 질문: 네 조건을 (i) 정책 수준 속성(상호배제·점유-대기·비선점이 허용되는지, 순환 대기가 가능한지)과 (ii) 상태 수준 술어(실제 순환, 그래프 축소 불가능성)로 나누고, 자원 모델(인스턴스 수, AND/OR/P-out-of-Q 요청, 재사용/소모성)별로 교착과 상태 술어의 관계, 정책 조건과 안전성의 관계를 한 틀에서 정리하고 증명할 수 있는가? 그 틀 위에서 기존 예방 기법(순서화, 일괄 요청, 선점, 천장 프로토콜, wound-wait)이 어떤 조건을 어떤 모델에서 깨는지 분류할 수 있는가?
- 근거: §1.1~1.2. 서술 불일치, 모델별 결과의 분산, 교육 자료 수준의 부분 증명.

'새 틀을 만든다'가 아니라 '문헌 결과의 통합 재정리, 기계 검사 가능한 정리표, 반례 카탈로그'로 둔다. 남는 후보는 1c2(대기 그래프 수준과 자원·용량 수준의 대응 조건)와 1e(기법별·모델별 건전성)이며 둘 다 가설이다. 대기 그래프 수준의 정리는 '재현'으로 분류한다. 위 질문의 문구는 G5에서 질문형으로 다시 쓴다.

### RQ2. 커널 현실 제한 가정 아래의 정확 판정 복잡도 (방향 B)

- 첫 작업: 제한 가정 후보와 각 가정의 실증 근거·한계 표. 복잡도 지도의 격자에는 이웃 문제 유형(PRED, VER, DIST)의 열을 두고 칸마다 같은 문제의 결과와 이웃 문제의 결과를 구분해 적는다.

### RQ3. 정책별 허용도–비용 프런티어 측정 (방향 C)

- 질문: 같은 자원·락 트레이스에서 순서화, 천장 프로토콜, wait-die/wound-wait, 뱅커 계열, 일괄 요청, 혼합 정책을 (a) 정확한 안전 오라클 대비 불필요한 거부·지연 비율, (b) 요청당 비용, (c) 롤백·대기 시간 분포로 측정하면 다른 정책에 지배되지 않는 설계점이 있는가?

### RQ5. 인터럽트·간접 호출을 포함한 조건 모델 확장 (방향 A)

### 4.1 잠정 우선순위

RQ6과 RQ3은 측정 중심이라 선행연구 결과와 무관하게 하네스를 재사용할 수 있어 먼저 착수하기 좋다. RQ1은 이론 기여 가능성이 있지만 중복 판정(§5)에 크게 좌우된다. RQ4는 중복 위험이 높아 새 주장보다는 비교·측정 항목으로 흡수하는 쪽이 안전해 보인다. RQ5와 RQ2는 커널 전문 지식과 데이터가 더 필요하며 Phase 3 결과를 보고 결정한다.

v0.3 주: Phase 3 결과(문서 04 §11.2)는 다음과 같다. RQ2는 M9(구조 조건 아래 다항 클래스)와 M38(락 중첩 여부에 따른 결정 가능성)이 이미 인접 경계를 주어 중복 위험을 높음으로 올렸고, G4에서 '부분'을 예상한다(해석). RQ4는 높음을 유지한다. RQ6는 재현 대상의 최소 건수를 사람이 정해야 한다(후보는 `refs/rq6-inventory.md`). RQ5는 H5a의 동기(자기 대기 비중)가 지지되며, 자기 대기를 조건 모델의 일부로 둘지 락 타입의 계약으로 볼지를 함께 검토할 질문 후보로 둔다(문서 04 §5, §6). 이 후보는 위 RQ5 본문에는 아직 넣지 않았다. 이 판단은 모두 AI 초안이다.

v0.4 주: G4(문서 05 §8)의 결과로 위 잠정 우선순위는 다음처럼 바뀐다(AI 초안, 사람 검토 전). RQ4는 RQ3의 정책 항목 P-INC로 흡수하므로 독립 질문이 아니다. RQ1은 문헌 결과의 통합 재정리와 기계 검사 가능한 정리표로, RQ2는 문헌 기반 복잡도 지도와 빈칸 후보 목록으로, RQ3은 OS·스레드 락 수준의 측정으로, RQ5는 필요(충분)조건과 lockdep 규칙의 정리 환원으로 좁힌다. RQ6은 조건부로 유지한다. 측정 중심의 RQ6과 RQ3이 먼저 착수하기 좋다는 판단은 그대로이며 실행 순서는 문서 02 §6.2에 있다(CP2는 사람 검토 뒤에 닫는다).
