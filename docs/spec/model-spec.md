## 2. 스냅샷 모델 SM

### 2.1 상태 [정의]

한 상태 s는 다음으로 이루어진다.

- 프로세스 n개(번호 0..n−1), 자원 종류 m개(번호 0..m−1).
- `cap[r]`: 종류 r의 단위 수(양의 정수).
- `alloc[p][r]`: 프로세스 p가 쥔 종류 r의 단위 수. 종류마다 합이 cap[r] 이하다.
- `alts[p]`: p의 대기 중인 요청. **대안(alternative)** 의 유한 집합이다. 대안은 길이 m의 0 이상 정수 벡터다. 비어 있으면 p는 대기 중이 아니다. p는 어떤 대안 하나를 통째로 얻을 수 있을 때 진행한다(DNF 형태).

기호: free(s)[r] = cap[r] − Σp alloc[p][r]. 집합 U에 대해 A(U) = Σp∈U alloc[p].

### 2.2 요청 형태의 표현 [정의]

| 요청 형태 | alts[p] |
|---|---|
| 단일 단위 | {e_r} (e_r은 r 성분만 1인 단위 벡터) |
| AND(여러 종류를 모두) | {v} (대안 하나) |
| OR(여러 종류 중 하나) | {e_r : r ∈ Q} |
| AND-OR | 대안 여러 개, 각각이 벡터 |
| P-out-of-Q | Q개 종류 중 서로 다른 P개를 고르는 모든 조합의 합 벡터 {Σr∈S e_r : S ⊆ Q, \|S\| = P} |

P-out-of-Q와 AND-OR는 표현은 되지만 대안 수가 조합적으로 늘어난다. 표현 통일과 크기 폭발 사이의 선택이다(결정 D3). M17(A−)이 AND와 OR를 P-out-of-Q의 특수한 경우로 서술한다는 것은 도구 요약으로 확인했다.

### 2.3 가정과 범위

| 번호 | 내용 | 성격 |
|---|---|---|
| A1 | 자원은 재사용 가능하고 배타적이며 선점되지 않는다. 쥔 단위는 보유자가 스스로 반납해야만 풀린다 | [가정] |
| A2 | 프로세스는 대기하는 동안 이미 쥔 단위를 계속 쥔다 | [가정] |
| A3 | 요청이 충족돼 진행하는 프로세스는 새 요청 없이 유한 시간 안에 끝나고 보유 전부를 반납한다. 이 가정은 완료 순서를 말하는 L3에만 필요하다 | [가정] |
| A4 | 요청은 프로세스가 자기 실행 문맥에서 자율적으로 낸다. 인터럽트에 의한 재진입처럼 다른 문맥이 대신 거는 의존은 포함하지 않는다(RQ5의 H5b에서 확장) | [가정] |
| W1 | 모든 대안의 모든 성분은 cap 이하다(alt[r] ≤ cap[r]). 용량을 넘는 요청은 어떤 상태에서도 충족될 수 없으므로 정의에서 제외한다 | [정의] |

v0.1의 범위 밖: 소모성 자원, 공유(읽기-쓰기) 모드, 선점 가능 자원, 시간 제약, 통신·조건 변수·세마포어 신호 대기에 의한 교착, 분산 시스템의 통신 지연, 재진입 가능 락(재진입 가능 락은 자기 대기가 없는 모델로 다룬다). 이 목록은 한계이며, 각 항목은 후속 모델 매개변수로 다룰 수 있다.

### 2.4 만족 [정의]

벡터 F에 대해 sat(alts, F)는 alts가 비어 있거나(대기하지 않음) 어떤 대안 a가 a ≤ F(성분별)이면 참이다. sat는 F에 대해 단조다. F가 커지면 참이 거짓이 되는 일은 없다.

상태 s가 **expedient**라는 것은 대기 중인 모든 프로세스 p에 대해 sat(alts[p], free(s))가 거짓인 것이다. 충족 가능한 요청은 이미 허용된 상태를 뜻한다.

## 3. 교착의 정의

### 3.1 교착 집합 [정의]

프로세스 집합 U가 s의 **교착 집합**이다 ⇔ U가 비어 있지 않고, U의 모든 p에 대해 alts[p]가 비어 있지 않으며 sat(alts[p], cap − A(U))가 거짓이다.

cap − A(U)는 U 바깥의 모든 프로세스가 끝나 자원을 전부 돌려주는 가장 유리한 경우에 U가 얻을 수 있는 최대량이다. 그때도 U의 누구도 진행할 수 없다는 뜻이다. s에 교착 집합이 있으면 s는 **교착 상태**다. 극소 교착 집합은 진부분집합이 교착 집합이 아닌 것이다.

이 정의는 본 연구의 선택이다(결정 D1). 레바인(F10, B)은 'deadlock'의 정의가 문헌마다 다르다고 지적하고 죽은 상태의 분류를 제안한다. 그 분류와의 대응은 원문을 읽은 뒤에 확정한다. 이 정의가 다루는 것은 자원 대기로 인한 영구 봉쇄(자원 교착)뿐이다.

### 3.2 동치 특징

| ID | 진술 | 상태 |
|---|---|---|
| L1 | 교착 집합 둘의 합집합은 교착 집합이다. 따라서 가장 큰 교착 집합이 있다 | [논증] [검증] |
| L2 | 가장 큰 교착 집합은 그래프 축소(만족되는 프로세스를 하나씩 끝내 자원을 돌려받기)를 더 못 할 때 남는 집합이다 | [논증] [검증] |
| L3 | 모든 프로세스를 끝낼 수 있는 순서가 있다(A3 아래) ⇔ 교착 집합이 없다. 검증은 순열 전수 탐색으로 했고 L2의 구현과 독립이다 | [논증] [검증] |

### 3.3 지속성 [논증]

P1: A1과 A2 아래에서 s의 교착 집합 U는 s에서 도달 가능한 모든 상태에서 교착 집합으로 남는다. U의 구성원은 아무것도 얻지 못하므로 A(U)가 변하지 않고, 구성원의 요청도 변하지 않기 때문이다. 외부 개입(중단, 선점)은 A1을 깨는 것이고, 탐지 후 복구가 하는 일이 바로 그것이다.

### 3.4 자기 대기와 FD [정의]

상태가 **FD(실현 가능한 총수요)** 를 만족한다는 것은 모든 대기 프로세스 p, p의 모든 대안 a, 모든 종류 r에 대해 alloc[p][r] + a[r] ≤ cap[r]인 것이다. FD가 깨진 대안이 있는 프로세스는 다른 누가 무엇을 반납해도 충족될 수 없는 자기 대기를 한다. 재진입 불가 락을 이미 쥔 채 다시 요청하는 이중 락이 그 예다(`P0: 보유 A, 요청 A`, 용량 1).

FD는 모델에 거는 선택 조건이다(결정 D2). 이중 락을 교착으로 세는지는 문헌의 정의(F1, F2, T9)에서 아직 대조하지 못했다. E2의 단일 스레드 교착 16건(문서 03 §3)이 이 경우에 해당할 수 있다는 것이 H5a다.

### 3.5 관찰 O1: 뱅커 알고리즘과의 관계 [정의에서 직접]

뱅커 모델의 상태는 (cap, alloc, max)이고 need = max − alloc이다. 안전 상태는 need를 차례로 만족시키며 모두 끝낼 수 있는 순서가 있는 상태다(F8, A). need ≠ 0인 프로세스의 alts를 {need}로 두고 need = 0인 프로세스는 alts를 비운 SM 상태 s_max를 만들면, L3에 의해 **안전 ⇔ s_max에 교착 집합이 없음**이다. 회피(K1)는 "허가한 뒤의 s_max에 교착 집합이 없을 것"을 검사하는 정책으로 읽을 수 있다. 이 읽기는 문서의 정의에서 바로 나오며 F8의 증명을 대신하지 않는다.

## 4. 상태 수준 술어(그래프) [정의]

- **의존 그래프 D(U)**: U 안의 p에서 q로 가는 간선은 p의 어떤 대안 a와 어떤 종류 r이 a[r] > cap[r] − A(U)[r]을 만족하고 q가 r의 단위를 쥐고 있을 때 있다(p = q 허용).
- **대기 그래프 WFG**: p에서 q로 가는 간선은 p의 어떤 대안이 r을 요구하고(a[r] > 0) q가 r의 단위를 쥐고 있을 때 있다(p = q 허용). 자유 단위가 있어도 간선을 만든다. 용량 1에서는 군더더기가 없고, 다중 단위에서는 과대 근사다.
- **자원 할당 그래프 RAG**: 프로세스와 자원 종류가 노드다. p → r은 p의 어떤 대안이 r을 요구할 때, r → q는 q가 r의 단위를 쥘 때 있다.
- **매듭(knot)**: RAG에서 노드가 둘 이상이고 밖으로 나가는 간선이 없는 강연결 성분이다.
- 문헌마다 매듭과 순환을 WFG(프로세스 노드만) 기준으로 정의하기도 한다. 본 문서의 매듭은 RAG 기준이다. 대응은 WP1.1에서 확인한다.

## 5. 코프만 조건의 층위 분리

네 조건은 층위가 다르다. 정책 수준 속성은 도달 가능한 상태의 집합을 정하고, 상태 수준 술어는 한 스냅샷의 성질이다.

| 조건 | 정책 수준 속성 | 상태 수준 술어(SM) | 정리 |
|---|---|---|---|
| 상호배제 | 자원 단위를 한 번에 한 프로세스만 쥘 수 있다 | 모델의 전제(A1)로 흡수된다. 공유 모드는 v0.1에 없다 | |
| 점유-대기 | 자원을 쥔 채 다른 자원을 요청하도록 허용한다 | HW: 대기 중이면서 단위를 쥔 프로세스가 있다 | T1(a) |
| 비선점 | 쥔 자원을 강제로 회수하지 않는다 | 모델의 전제(A1). 선점 정책은 상태 정의가 아니라 **전이**를 바꾼다 | |
| 순환 대기 | 요청에 순서나 우선 규칙을 적용하지 않는다 | D(U)가 강연결이다. FD이면 길이 2 이상의 순환이 있다 | T1(b)(d) |

해석 [논증]: 극소 교착 집합에서는 점유-대기와 순환 대기가 성립하고(FD 아래에서 순환은 길이 2 이상), 이 둘은 서로 독립이 아니다. 극소 교착 집합이 강연결이면 구성원이 모두 단위를 쥐고 다른 구성원을 기다린다. 이는 실버샤츠 교과서 사본(T1, C)이 순환 대기가 점유-대기를 함의한다고 쓴 것(문서 01 §1.1-5)과 같은 방향이다. 단, 여기서 얻은 함의는 극소 교착 집합이라는 한정이 붙은 상태 수준 명제이고, 교재의 서술이 어떤 층위의 명제인지는 확인하지 않았다. FD가 깨지면 길이 1의 순환(자기 대기)이 남는다.

네 조건이 갖춰져도 교착이 아닐 수 있다(RAG에 순환이 있어도 교착이 아닌 반례: §7의 OR 예). 정책 수준에서 어느 조건을 제거했다고 말하려면 그 제거가 어떤 상태 불변식을 보장하고 그 불변식이 교착 집합 부재를 함의함을 보여야 한다. §6의 T6, T7, T8이 그 형태의 보조정리다.

### 6.1 증명 스케치 [논증]

사람 검토 전이며 기계 검사를 하지 않았다.

- **L1.** A(U ∪ V) ≥ A(U)이므로 cap − A(U ∪ V) ≤ cap − A(U)이다. sat는 단조이므로 U의 구성원은 더 작은 벡터에서도 막혀 있다. V도 같다.
- **L2.** 축소가 끝난 뒤 남은 집합 R은 free + A(제거된 집합) = cap − A(R)에서 모두 막혀 있으므로 교착 집합이다. 교착 집합 U의 구성원 중 축소가 처음 제거한 p를 가정하면 그때의 가용량은 cap − A(U) 이하이므로 p는 만족될 수 없다. 모순이다.
- **L3.** 축소의 제거 순서가 완료 순서다. 거꾸로 완료 순서가 있으면 단조성 때문에 축소도 모두 제거한다.
- **T1.** (a) 극소 U의 p가 아무것도 쥐지 않았다면 \|U\| ≥ 2일 때 A(U ∖ {p}) = A(U)이므로 U ∖ {p}가 더 작은 교착 집합이다. \|U\| = 1이면 cap − 0 = cap에서도 막혀 있어 W1에 어긋난다. (b) D(U)의 끝 강연결 성분 C(밖으로 가는 간선이 없는 성분)를 잡는다. p ∈ C의 각 대안은 어떤 r에서 막혀 있고(W1에 의해 A(U)[r] > 0), r을 쥔 U의 구성원은 모두 p의 이웃이라 C 안에 있다. 따라서 A(C)[r] = A(U)[r]이고 C도 교착 집합이다. 극소성에 의해 C = U다. 크기 1이면 W1에 의해 p가 막힌 r을 직접 쥐고 있어 자기 간선이 있다. (c) \|U\| = 1이면 어떤 대안 a가 a[r] > cap[r] − alloc[p][r]이어야 하는데 FD는 이를 금한다. (d) (b)와 (c)에서 강연결이고 노드가 둘 이상이므로 길이 2 이상의 순환이 있다.
- **T2.** (⇐) 순환의 구성원 U에서 순환의 각 간선은 용량 1인 종류 r을 U의 다른 구성원이 쥐고 있다는 뜻이므로 cap − A(U)[r] = 0이고 대안(통째로 얻어야 하는 벡터)이 막힌다. (⇒) T2n.
- **T3.** (i) 교착 집합 U의 구성원이 요청하는 모든 종류 r은 cap[r] − A(U)[r] = 0이므로 그 단위는 모두 U가 쥐고 있다. 프로세스 노드 U와 그 요청 종류의 노드 집합은 후속 노드에 대해 닫혀 있고 모든 노드에 후속이 있으므로 끝 강연결 성분에 순환이 있고 매듭이 된다. (ii) 매듭 K의 프로세스 집합을 U로 하면 요청 종류의 모든 보유자가 U 안에 있고, expedient에 의해 요청 종류의 free가 0이므로 cap − A(U)[r] = 0이다.
- **T5(a).** 매듭 K의 프로세스 집합을 U로 하자. p ∈ U의 대안 a는 expedient에 의해 어떤 r에서 a[r] > free[r] ≥ 0이므로 r은 p의 요청 종류이고 K 안에 있다. K가 닫혀 있으므로 r의 보유자는 모두 U 안에 있어 cap[r] − A(U)[r] = free[r] < a[r]이다. 모든 대안이 막히므로 U는 교착 집합이다. **T5(c).** T2n.
- **T6.** U가 교착 집합이면 U의 각 구성원 p는 어떤 r에서 막혀 있고(W1에 의해 A(U)[r] > 0) r의 보유자 q ∈ U가 있다. ORD에 의해 r > f(p)이고 f(q) ≥ r이다(f는 쥔 종류의 최대 번호, 없으면 −1). 따라서 f가 엄밀히 증가하는 열을 만들 수 있고, U가 유한하므로 모순이다.
- **T7.** 교착 집합의 구성원은 막혀 있는 종류의 보유자가 U 안에 있어야 하는데(W1), U의 구성원은 대기 중이므로 ALL에 의해 아무것도 쥐지 않는다. 모순이다.
- **T8.** TS 아래에서 D(U)의 간선은 WFG의 간선이고 서로 다른 프로세스 사이의 간선은 모두 같은 방향이므로 길이 2 이상의 순환이 없다. FD와 T1(c)(d)에 의해 극소 교착 집합이 있을 수 없다.

## 8. 정책 분류와 정보 수준

### 8.1 예방, 회피, 탐지 [정의]

정책은 허용 가능한 전이(허가, 거부, 지연, 중단, 선점)를 정하는 규칙이다. 정보 수준은 문서 02 §4의 작업 가설이다(문헌 분류가 아님): K0 현재 상태만, K1 최대 요구량 선언, K2 락 클래스 순서·의존 정보, K3 프로그램 전체 정보.

- **예방**: 정책이 상태 불변식 I를 유지하고 I가 교착 집합 부재를 함의함(§6의 T6, T7, T8 같은 보조정리)을 정적으로 보일 수 있다. 허가 결정이 최대 요구에 대한 안전 순서 탐색을 요구하지 않는다.
- **회피**: 허가 결정이 허가 후의 상태가 안전한지(§3.5의 O1) 검사하는 데 의존한다. 선언된 최대 요구(K1 이상)가 필요하다.
- **탐지**: 교착 상태에 도달할 수 있음을 허용하고 도달한 뒤 교착 집합(L2)을 찾아 복구한다. 복구는 A1을 깨는 외부 개입(중단, 선점)이다.

예방과 회피를 가르는 경계는 판단이 필요한 사례를 남긴다(결정 D4). 이 문서의 선택은 위와 같고, 아래 분류는 잠정이다.

### 8.2 안전 상태 [정의]

§3.5의 O1이 정의다. 불안전 상태는 교착 상태가 아니다.

| P-ALL | 일괄 요청 | 점유-대기 | ALL → T7 | K1(필요 자원 선언) | 예방 |
| P-RET | 반납 후 재시도(trylock + 백오프) | 대기 중 보유(비선점의 우회) | ALL → T7 | K0 | 예방. 기아와 라이브락은 별도 문제 |
| P-WD | wait-die | 순환 대기 | TS → T8, FD 필요 | K0 + 프로세스 속성(타임스탬프) | 예방 |
| P-WW | wound-wait | 순환 대기, 비선점 | TS → T8, FD 필요 | K0 + 프로세스 속성 | 예방(선점형) |
| P-PCP | 우선순위 천장 프로토콜 | 순환 대기 | 이 문서에서 불변식을 아직 형식화하지 않음 | K2(천장 값은 미래 사용 정보) | 예방/회피 경계. 허가가 현재 잠금 상태와 천장 값 비교에 의존하지만 안전 순서 탐색은 하지 않는다. 결정 D4 |
| P-BNK | 뱅커 알고리즘 | (조건 제거 아님) | s_max에 교착 집합 없음(O1) | K1 | 회피 |
| P-RAG | 단일 인스턴스 그래프 기반 회피 | (조건 제거 아님) | 청구 간선 포함 순환 검사 | K1 | 회피(교재 서술, C) |
| B0 | 무정책 | — | — | K0 | 해당 없음 |
| B1 | 주기적 WFG 탐지 + 희생자 선택 | — | 교착 집합을 L2로 찾음 | K0 | 탐지 |

주의: wait-die와 wound-wait의 불변식 TS는 요청 시점뿐 아니라 락이 대기자에게 넘어가는 시점에도 유지해야 한다. 이미 대기 중인 프로세스가 나이 어린 쪽이 나이 많은 쪽을 기다리게 되는 일이 생기지 않는지는 정책 구현에서 확인할 항목이다(WP3.1). T8은 불변식이 유지될 때만 말한다.

## 9. 사람이 정해야 하는 것과 알려진 한계

결정 항목:

| 번호 | 내용 | 제안 |
|---|---|---|
| D1 | 교착의 기본 정의로 §3.1의 교착 집합을 쓴다 | 채택. 대안은 도달 가능성 기반 정의 |
| D2 | 자기 대기(이중 락)를 교착에 포함하고 FD를 선택 조건으로 둔다 | 채택. F1, F2 원문과 E2 사례 코딩(RQ5)이 끝나기 전까지 잠정 |
| D3 | AND-OR와 P-out-of-Q를 DNF 대안으로 통일한다 | 채택. 대안 수 폭발은 크기 한계로 문서화 |
| D4 | 예방과 회피의 경계 정의(§8.1)와 P-PCP 분류 | 잠정 분류를 검토해 확정 |
| D5 | 인터럽트 재진입 같은 비자율 의존(A4)을 SM 밖 확장(RQ5)으로 둔다 | 채택. SM에 의존 간선 일반화를 넣는 대안이 있다 |
| D6 | 정책 수준 속성을 상태 불변식으로 형식화한다(전이 제약이 아니라) | 채택. P-PCP처럼 불변식이 분명하지 않은 정책이 있다 |

알려진 한계:

- 전수 검증의 범위가 작다(§6). 통과는 정리의 증명이 아니다.
- 오라클(`oracle/sm.py`), 정리 진술, 검증이 모두 같은 정의에서 나왔다. 정의와 구현과 정리가 서로 어긋나지 않는다는 것은 확인했지만, 이 정의가 문헌의 교착과 같다는 것은 확인하지 못했다. L3의 순열 탐색은 L2 구현과 독립이지만 정의를 공유한다.
- SI-2의 완료 기준인 Alloy 또는 TLA+(TLC)로의 교차 검증은 하지 않았다. 도구는 작업공간에서 실행되는 것까지 확인했다(문서 02 §1.3).
- 증명은 스케치이고 기계 검증이 없다(WP1.5 선택 항목).
- 문헌 대조를 하지 못했다. F1, F2, F3 원문이 없다(문서 03 §9).
- 정리표(`docs/rq1/theorems.md`)와 정의 비교표(`docs/rq1/definitions.md`)는 만들지 않았다. 정리 진술은 §6에 임시로 둔다.
