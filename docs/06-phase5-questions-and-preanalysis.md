- 작성일: 2026-11-01 (KST)

- 상태: **G5 미통과. AI 초안 단계이며 동결 전이다.** 'RQ 확정'이 아니다. 어떤 연구 질문도 새롭다고 쓰지 않는다.
- 관련 문서: 문서 02 §3(게이트), §5(연구별 계획), §7(품질 관리와 사전 분석 계획의 항목), §10(확정할 사항), 문서 05 §8(G4 판정과 RQ별 결정), `prereg/`(공통 규약과 사전 분석 계획 초안 5개)

## 0. 한 페이지 요약

- G5의 통과 조건은 'RQ 확정, 사전 분석 계획 커밋'이고, 통과하면 새 아이디어의 구현, 본 실험, 증명이 해제된다(문서 02 §3). 이 문서와 `prereg/`는 그 입력 초안이다. 확정과 동결은 사람이 한다.
- 한 일: 문서 02의 가설 H1–H6을 질문형으로 다시 썼다(§2). RQ6, RQ3(P-INC 포함), RQ1, RQ5, RQ2의 사전 분석 계획 초안과 공통 통계·측정 규약을 썼다(`prereg/`). RQ4는 G4 판정(AI 초안)대로 RQ3의 정책 항목 P-INC로 흡수했다. 이 흡수는 CP2에서 사람이 확정한다.
- RQ6의 파일럿(B-6)을 마쳤다(`docs/rq6/pilot.md` v0.2, 자료 `experiments/pilot/`). 시간, 분산, 비용, 동률, 난이도, 재현성 같은 운영 수치만 보고했고 어떤 주장이 유지되는지는 말하지 않는다. 파일럿이 새로 연 결정은 O6-10–O6-12이고(§5.2) 모두 AI 초안이며 사람의 검토 전이다.
- 하지 않은 것: 동결 태그, 'RQ 확정'이라는 서술, 본 실험, 새 아이디어의 구현과 증명 완성. 수치 임계값은 모두 '계획용 값'이며 근거가 있는 값이 아니다(§5.3).
- G5를 G3, G4처럼 '조건부 통과(AI 초안)'로 쓰고 넘어가지 않는 이유: G3와 G4가 해제한 것은 조사의 후속, 측정 도구와 준비 작업, 판정에 따른 결정이어서 AI 초안 단계에서 이어 가도 나중에 고칠 수 있었다. G5가 해제하는 본 실험, 새 아이디어의 구현, 증명은 계획을 결과를 보기 전에 고정해 두었다는 사실이 가치다. AI가 스스로 동결하고 그 위에서 실행하면 검토자 없는 동결이 되어 사전 등록의 구실을 하지 못한다. 그래서 G5는 사람의 검토와 동결 뒤에만 통과로 쓴다(§6).
- 동결을 막는 결정은 §5에 모았다. 먼저 정할 것은 Q9(G4 판정 검토와 질문형 재작성 방향), Q8(RQ6의 재현 최소 건수), 모델 명세의 D1–D6(G2 동결)이다.

## 1. 입력과 방법

입력은 G4의 RQ별 결정(진행 1: RQ6 조건부 유지, 좁힘 4: RQ1, RQ2, RQ3, RQ5, 흡수 1: RQ4, 중단 0. 문서 05 §2.5, §3.5, §4.5, §5.5, §6.5, §7.5와 §8.3), 문서 02 §5의 작업 패키지, §7의 양식(가설, 데이터·워크로드·제외 기준, 지표와 계산식, 비교·통계 절차, 판정 규칙, 허용되는 사후 변경)이다. 방법은 다음과 같다.

1. 문서 05의 질문형 예시 문구를 바탕으로 하되, 결과를 미리 정한 것처럼 읽히는 서술과 새로움을 뜻하는 서술을 뺐다.
2. 반증 조건을 명제마다 적었다. 측정이 아닌 연구(RQ1, RQ2)에서는 반례, 문헌 발견, 시간 상자 만료가 반증·종결 조건이다.
3. 지표, 통계, 판정의 구체값은 파일에 적고, 근거가 없는 값은 '계획용'이라 표시해 열린 항목으로 올렸다.
4. AI가 새로 정한 정의와 규칙(예: RQ3의 지표 M1에서 '오라클 허용 가능 요청', RQ6의 '보류' 상태, RQ5의 수치 규칙)은 AI의 제안이다. 사람이 특히 검토할 곳을 §7에 따로 적었다.

## 3. 동결 전에 할 수 있는 일과 없는 일

문서 02 §3은 G5 이전에 ① 오라클·하네스 같은 측정 도구, ② 기존 알고리즘의 기준 구현, ③ 정의·정리 초안(증명 완성은 제외)을 허용한다. `prereg/README.md` §2는 여기에 문헌 변형의 재구현(문헌 예제를 재현하는 데까지)과 파일럿(분산 추정, 코더 일치도)을 더했다. 파일럿을 더한 것은 AI의 해석이며, 사전 분석 계획이 반복 수와 코더 일치도를 파일럿으로 정하게 되어 있기 때문이다. 계획이 정한 지표를 정한 입력군에서 재는 본 실행과 그 분석, 새 아이디어의 구현과 증명 완성, 'RQ 확정'이라는 서술은 동결 뒤에 한다.

## 4. 공통 통계·측정 규약

측정을 하는 RQ6과 RQ3은 `prereg/README.md` §4의 SP-1–SP-8을 따른다. RQ1, RQ5, RQ2는 필요한 부분만 인용한다. 선택한 방법은 다음과 같다.

- 독립 단위는 시드로 만든 입력 인스턴스이고, 같은 시드의 인스턴스를 모든 정책에 주는 짝지은 비교와 실행 순서의 무작위화를 쓴다(SP-1). 벽시계 시간은 다단계 반복 설계(P2)와 실험 설정의 기록·무작위화(P4)를 따른다. 작업공간은 코어 2개를 공유하므로 절대 시간이 아니라 정책 사이의 상대 비율과 입력 크기에 따른 기울기만 주장한다.
- 구간은 시드를 단위로 한 백분위 부트스트랩으로 구하고, 정책 사이 비교는 짝지은 비율의 기하평균과 같은 방법의 구간을 쓴다(SP-2).
- 지표는 작을수록 좋은 방향으로 정의한다. A가 B보다 '나쁘지 않다'는 비율 구간의 상한이 1 + δ 이하라는 뜻이고, 지배는 모든 주 지표에서 나쁘지 않고 하나 이상에서 유의하게 좋다는 뜻이다. 가르지 못하면 순위를 억지로 매기지 않고 '미결정'으로 보고한다(SP-3).
- 머리 주장은 가족으로 사전에 나열하고 가족 크기 k로 구간 수준을 1 − 0.05/k로 올린다. 가족에 없는 비교는 '탐색적'으로 표시한다(SP-4).
- 구현은 소규모 전수 검사(교착 0), 오라클 차등 테스트, 속성 기반 테스트를 통과하기 전에는 결과 분석에 쓰지 않는다(SP-5). 반증, 비교 불가, 미결정도 같은 형식으로 보고하고 원자료를 보존한다(SP-6). 결과 주장은 주장 대장에 올리고(SP-7), '새롭다'와 '독립 재현이 없다'를 쓰지 않는다(SP-8).

## 7. 사람이 특히 검토할 설계 선택

초안에서 AI가 새로 정한 것이라 틀렸을 가능성이 있는 곳이다.

1. RQ3의 지표 M1 정의: '오라클 허용 가능 요청'과 '제한'의 정의(`prereg/RQ3.md` §5)가 정책 사이에서 공정한지.
2. RQ3의 정책 응답 의미(결정적 거부는 재시도 없이 실패)와 P-INC의 두 변형 F와 R(`prereg/RQ3.md` §4.2, §4.3).
3. RQ3의 머리 주장 가족과 구간 수준 보정(Bonferroni형)이 너무 보수적이지 않은지, 요구하는 시드 수(계획용 200)를 감당할 수 있는지.
4. RQ6의 '보류' 상태를 다섯 범주 밖의 상태로 두는 것, 복잡도 주장의 허용 오차 ε(`prereg/RQ6.md` §7).
5. RQ5의 수치 규칙(H5a-q의 10%, H5b-q의 x_min = 5, H5c-q의 0.70)과 읽기 기반 코딩에서 AI를 두 번째 코더로 쓰는 것(`prereg/RQ5.md` §3, §4).
6. RQ1의 분류(R, D, X, G, N)와 '어긋남(X)'을 문헌의 오류로 읽지 않는 규칙(`prereg/RQ1.md` §6).
7. RQ2의 칸 상태 분류와 '빈칸 후보'의 조건(`prereg/RQ2.md` §4).

## 8. 한계

- 초안 전체가 AI의 작성이며 사람의 검토 전이다. 근거가 없는 수치는 '계획용'으로 표시했다.
- 설계는 모델 명세(G2 잠정)와 G4 판정(조건부 통과, AI 초안)에 의존한다. 둘 중 하나가 바뀌면 파일도 바뀐다.
- G4의 한계를 그대로 물려받는다. 정방향 인용 추적을 하지 못했고, 본문 대신 도구 요약·초록에 기댄 판정이 많으며, '없음'과 '찾지 못함'은 부재 증명이 아니다(문서 05 §8.5).
- 원문 PDF가 필요한 곳이 많다(RQ별 목록은 문서 05 §8.4의 5항과 각 파일의 열린 항목).
