# DeadlockConditionRedefinitionAndPrevention

교착상태 조건의 재정의와 효율적인 예방 알고리즘에 대한 연구 작업공간이다. 코프만의 네 조건(상호 배제, 점유 대기, 비선점, 순환 대기)을 다시 검토하고, 교착 예방·회피 정책을 같은 조건에서 비교하는 것이 목표다. 연구 질문은 아직 확정하지 않았고 어떤 아이디어도 새롭다고 주장하지 않는다. 새롭다는 판정은 선행연구 게이트(`docs/01-…` §5)를 통과한 뒤에만 한다.

> AI(Claude)가 작성한 초안이며 사람의 검토 전이다. 문헌 서술 가운데에는 원문을 직접 읽지 못하고 초록·서지 페이지·열람 도구의 요약으로 확인한 것이 많다. 서술마다 확인 수준(A, A−, B, C, D, X)을 붙였고 C 이하는 논증의 전제로 쓰지 않는다.

## 검사 실행

표준 라이브러리만 쓰는 Python 3 스크립트다.

```
python3 -I oracle/check_sm.py formal/rq1/sm-check-results.md          # 약 1분
python3 -I oracle/mutation_check.py formal/rq1/sm-mutation-results.md # 약 1.5분
```

10개 소규모 범위(프로세스 3–4개, 자원 종류 2–3개, 용량 1–3)의 595,676개 상태에서 정리 진술 위반이 0건이다. 증명이 아니다. 오라클, 정리 진술, 검증이 같은 정의에서 나왔으므로 정의 내부의 일관성만 보여 준다(`oracle/README.md`).

RQ6용 하니스, 기준 구현, 문헌 변형, 파일럿 도구와 RQ3용 정책·생성기·트레이스 도구의 점검 실행법은 `bench/README.md`의 '실행'에 있다. RQ3의 정책 전수 검사(`bench/check_lock_policies.py`)는 코어 2개에서 약 10분이 걸린다.

RQ5 코드북 도구와 RQ2 격자 문서의 점검은 1초 안에 끝난다. 두 보고서는 다시 실행해도 같은 내용이 나온다.

```
python3 -I analysis/rq5/check_codebook_tools.py formal/rq5/codebook-tools-check.md
python3 -I analysis/rq2/check_grid.py --report formal/rq2/grid-check.md
```
