# prereg/RQ2 — 제한 가정 아래 정확 판정의 복잡도 지도와 빈칸 후보 (AI 초안 v0.1)

- 작성일: 2026-11-01 (KST) · 작성: Claude(AI 조수) · 사람의 검토 전 · **동결 아님**
- 근거: 문서 02 §5.6, 문서 05 §3(G4 판정과 §3.5 결정), 문서 04 §4(복잡도 경계 지도), 모델 명세, `prereg/README.md`
- 이 RQ는 측정이 아니라 문헌 지도 작성과 시간 상자 안의 증명 시도다. 통계 규약(SP-1–SP-4)은 적용하지 않고 SP-6, SP-7, SP-8, 양성 결과에 대한 SP-5만 적용한다.
- 코드: 문제 유형 DET, SAFE, MAXP, PRED, VER, DIST와 하위 주장 2a–2g는 문서 05 §3.1의 것이다. 지표 코드 M1–M8과 문헌 ID M1–M129는 '지표 M1', '문헌 M9'처럼 구분한다.

## 1. 질문

SAFE(안전 상태 판정)에서 순환 길이, 중첩 깊이, 인터럽트 문맥으로 정의한 클래스 가운데 문헌이 복잡도를 정하지 않은 칸은 어디인가? DET(현재 상태 교착 판정)와 MAXP(가장 허용적인 정책의 계산)에서는 어떤가?

하위 질문:

- Q2-1 (2a–2c) 정보 수준(K0–K3) × 구조 제한 × 질문 유형의 격자에서 칸마다 알려진 복잡도와 출처, 가정은 무엇인가? '같은 문제의 결과'와 '이웃 문제(PRED, VER, DIST)의 결과'를 구분해서.
- Q2-2 (2d–2g) 순환 길이 제한, 중첩 깊이·락 수 매개변수, 인터럽트·우선순위 문맥, 실증 분포로 정당화한 제한으로 정의한 클래스 가운데 복잡도가 문헌에서 정해지지 않은 칸은 어디인가? (빈칸 후보 목록)
- Q2-3 원문을 확인한 뒤에도 비어 있는 칸 가운데 시간 상자 안에서 증명, 반증, 또는 막힌 지점의 기록을 낼 수 있는 것은 무엇인가?
- Q2-4 (2g) 실증 분포(E1, E2)로 정당화한 제한을 프로그램이나 상태 공간에 대해 검사할 수 있는 성질로 바꾸면 그 클래스의 소속을 검사하는 비용은 얼마인가?

## 2. 주장하지 않는 것

- '문헌 밖에도 존재한다'는 서술(옛 H2의 문구)과 새로움 주장. 빈칸 후보는 가설이며 없다는 주장이 아니다.
- 이웃 문제 유형의 복잡도를 SAFE의 결과로 옮기는 서술. 같은 제한을 쓰더라도 다른 문제의 결과다.
- E1, E2가 시스템 클래스를 정의한다는 서술. 보고된 교착 사례의 크기 분포일 뿐이다. 문서 01·02의 '98.5%'는 전체 동시성 버그 기준이고 교착만 보면 47/49(95.9%)다.
- S9의 Thm 3.1(상수 중첩 깊이에서도 NP-난해)을 근거로 쓰는 것. 증명이 쓰는 깊이 상한이 진술과 맞지 않아 보인다는 도구 지적이 있어 원문 대조 전에는 쓰지 않는다.
- 문헌 M9의 모델(제조 시스템의 순차 자원 할당)이 OS 락 프로그램(중첩 획득, 한 스레드가 락 여럿을 보유)과 대응한다는 서술. 대응은 따져 보지 않았다.

## 3. 검토할 명제와 반증 조건

| 명제 | 반증하는 관측 |

| P2-b §6의 빈칸 후보 (i)–(iii)에 대해 문헌에 같은 문제의 결과가 없다 | 원문, 정방향 인용 추적, 사람이 제공한 PDF에서 같은 문제·같은 제한의 결과가 발견되면 그 후보는 '문헌에서 발견'으로 바꾼다(2d–2g가 '동일'로 바뀔 수 있다) |
| P2-c 빈칸 후보에 대해 시간 상자 안에서 증명 또는 알고리즘이 나온다 | 시간 상자 만료. 반증이 아니라 '막힌 지점 기록'이 결과다 |
| P2-d 양성 결과(다항 알고리즘)가 정확 오라클과 소규모에서 일치한다 | 한 입력에서라도 불일치. 구현과 증명을 모두 재검토하고 결과 보류 |

## 4. 격자와 칸의 상태

**축.** 질문 유형 6개(DET, SAFE, MAXP, PRED, VER, DIST). 정보 수준 K0–K3(문서 02 §4. 본 계획의 작업 가설). 구조 제한은 다음 목록에서 시작한다(추가 가능):

| 코드 | 구조 제한 | 비고 |
|---|---|---|
| R0 | 제한 없음 | 기준선 |
| R1 | 교착 순환 길이 2 이하 | 검사할 수 있는 성질로 정식화한 뒤에 칸을 채운다 |
| R2 | 락 중첩 깊이 k (상수로 고정한 칸과 입력 매개변수인 칸을 따로) | |
| R3 | 락 수 ℓ 이하 | |
| R4 | 인터럽트·우선순위 문맥 포함 | RQ5의 EM(`prereg/RQ5.md` §6)에 의존 |
| R5 | 단일 인스턴스(용량 1) | |
| R6 | 문헌 M9 §5의 구조 조건(RC1, SR1, SR2, CB1, CB2) | 제조 시스템의 경로 구조. 락 프로그램 구조와 다름 |
| R7 | 종료 요청이 생산자·소비자형(Gold 1978) | 2차 서술 경유 |

**칸의 기록.** 문제 정의(입력과 질문), 모델 가정(요청 형태, 단위 수, 선점, 재사용·소모성), 복잡도 결과(상한·하한·완전성, 매개변수 체제), 출처(ID, 정리 번호, 쪽), 확인 수준(A, A−, B, C), 같은 문제의 결과인지 여부, 상태.

**상태 분류(칸마다 하나).**

| 상태 | 조건 |
|---|---|
| 알려짐 | 같은 문제, 같은 제한의 결과가 A 또는 A− 출처에 있다(정리 번호와 가정을 적는다). 정리 번호와 수치는 열람 도구 요약(M52–M54, S9)이면 '원문 재확인 필요' 표시 |
| 2차 서술 | 결과를 2차 문헌 경유로만 안다(Gold 1978, Araki 외 1977는 문헌 M9 경유). 원문 확인 전에는 '알려짐'으로 올리지 않는다 |
| 이웃만 | 이웃 문제 유형(PRED, VER, DIST)에만 결과가 있다. 이 칸의 결과로 쓰지 않는다 |
| 빈칸 후보 | 이번 검색 범위에서 같은 문제의 결과를 찾지 못했다. 부재 증명이 아니며 정방향 인용 추적이 비어 있으면 '인용 추적 미완'을 병기한다 |
| 미확인 | 점검이 끝나지 않았다(원문 미열람 등). 빈칸 후보로 올리지 않는다 |

증거 규칙: 수준 C 이하의 출처는 '알려짐'의 근거가 아니다. 초록(B) 수준의 결과는 '알려짐(초록 수준)'으로 따로 표시한다. 상태가 바뀌면 이전 상태, 새 상태, 출처를 변경 기록에 적는다.

## 5. 실증 근거의 사용 규칙 (WP2.3)

E1(교착의 97%, 30/31이 자원 2개 이하)과 E2(교착 49건 중 47건, 95.9%가 실행 문맥 2개 이하이며 이 열이 논문의 스레드 수 정의와 같은지는 확인 전)는 동기를 주는 증거일 뿐 클래스를 정의하지 않는다. 제한마다 한 행에 (a) 검사할 수 있는 성질로의 정식화, (b) 그 성질을 검사하는 비용, (c) 실증 분포가 지지하는 정도(수치와 표본 한계)를 함께 적는다. 문서 05 §3.4의 2g에 해당하는 칸부터 우선순위를 매긴다. 우선순위표는 시도 전에 커밋한다.

## 6. 빈칸 후보와 증명 시도의 규약 (WP2.4)

현재 보이는 후보는 가설이다(문서 05 §3.5의 3항):

- (i) SAFE × 중앙 집중 온라인 정확 회피 × 락 중첩 깊이 k
- (ii) SAFE × 교착 순환 길이 2 이하(검사할 수 있는 성질로 정식화한 뒤)
- (iii) 인터럽트 문맥을 포함한 모델의 DET·SAFE (RQ5의 EM이 정의된 뒤에만 정식화할 수 있다)

**시도 전 정식화.** 후보마다 `docs/rq2/grid.md`에 결정 문제를 먼저 쓰고 사람이 검토한 뒤에만 시도한다: 입력(프로그램 또는 상태의 형식), 모델 가정, 제한(고정 상수인가 매개변수인가), 질문, 기대하는 결과의 형태(다항 알고리즘, 난해성 환원, 매개변수 곡선). 정식화에서 문헌의 가장 가까운 결과(문헌 M9, M38, M50–M54)와의 차이를 한 단락으로 적는다.

**시도의 조건.** 원문을 확인한 뒤에도 비어 있는 칸에만 시간 상자를 쓴다(문서 05 §3.5의 3항). 시간 상자는 RQ2 전체 8주이고 이 안에서 증명·알고리즘 시도(WP2.4)에 약 3주를 쓴다(문서 02 §5.6. 가정). 후보마다 최대 1주, 순서는 (i), (ii), (iii)이며 사람이 바꿀 수 있다. 시도마다 접근법, 결과, 막힌 지점을 `formal/rq2/attempts.md`에 적는다. 실패한 접근도 기록한다.

**결과 분류.** S 완결(증명 또는 알고리즘이 있고 사람 검토를 통과), P 부분 결과(한정된 하위 클래스에서의 결과나 환원이 막힌 지점), F 진전 없음(막힌 지점 기록).

**양성 결과의 검증.** 다항 알고리즘이 나오면 구현해 정확 오라클(SI-2의 O2)과 소규모에서 차등 테스트한 뒤에 보고한다(SP-5, P2-d). 난해성 증명은 실험이 아니라 사람 검토로 확인하고 소규모 기계 검사는 환원 가젯의 점검에 쓸 수 있다.

## 7. 판정 규칙

- **성공.** 격자의 모든 칸에 상태가 있고, 빈칸 후보 목록이 점검 기록(어느 문헌, 어느 질의, 어느 쪽을 읽었는지)과 함께 제시되며, 이웃 문제의 결과가 '이웃만'으로 분리되어 있다. 시도 결과(S, P, F)는 있는 대로 보고한다.
- **부분.** '미확인' 칸이 전체의 30%를 넘으면(계획용 값) 지도를 '잠정'이라고 표시하고 결론에서 그 칸을 뺀다(원문 PDF 미확보 때문일 가능성이 크다).
- **종결.** 시간 상자가 만료되고 진전이 없으면 문헌 기반 복잡도 지도와 미해결 칸 목록으로 종결한다(문서 02 §5.6의 중단 규칙). 이 경우를 실패라고 쓰지 않고 결과로 보고한다.
- **문헌 발견.** 후보가 문헌에서 발견되면 그 후보는 '문헌에서 발견'으로 바꾸고 해당 하위 주장(2d–2g)의 G4 판정을 갱신한다. 모든 후보가 그렇게 되면 지도만 산출물로 삼고 종료한다.
- 결과 서술에서 '새롭다', '처음이다'를 쓰지 않는다(SP-8).

## 8. 허용되는 사후 변경

허용(기록하고 본 결과가 있는지 표시): 격자의 행·열 추가, 원문을 읽은 뒤 칸의 상태 갱신(이전·이후 상태와 출처 기록), 시도 순서의 변경(사유 기록), 정식화의 수정(시도 전).

허용하지 않음: 후보가 문헌에서 발견된 뒤 목록에서 조용히 빼는 것, '빈칸 후보'의 조건을 결과를 본 뒤 바꾸는 것, 이웃 문제의 결과를 SAFE 칸으로 옮기는 것, 시간 상자를 결과가 마음에 들지 않는다는 이유로 연장하는 것(연장은 사람의 결정과 사유 기록이 있을 때만).

## 10. 한계

- 칸의 근거 대부분이 도구 요약(A−)이나 초록(B)이다. 정리 번호와 수치는 원문 재확인 전이다(M52–M54, S9).
- 2차 서술 경유(Gold, Araki)는 원문이 아니다. 문헌 M9의 모델과 OS 락 프로그램의 대응은 따져 보지 않았다.
- 정방향 인용 추적을 일부만 했다(RQ2의 M9 인용 추적은 오류로 실패). 영어 중심 웹 검색이며 이웃 분야(제조 시스템, 이산사건 시스템, 프로그램 검증)의 문헌이 많아 겹침을 놓칠 수 있다.
- 중복 위험은 높음이다(문서 05 §3.5의 4항). '빈칸 후보'가 원문 확인에서 사라지는 것이 정상 결과일 수 있다.
- RQ2는 RQ1의 정의와 RQ5의 자료에 의존하므로 일정상 마지막에 오며, 앞 단계가 늦어지면 이 계획의 시간 상자가 줄어든다.
