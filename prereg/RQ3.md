## 1. 질문

OS·스레드 락 수준의 정책 집합(락 클래스 순서화, 일괄 요청, 반납 후 재시도, wait-die, wound-wait, 천장, 뱅커, 혼합, 증분 순서 승인)에서도 데이터베이스 2PL 비교와 같은 방향의 순위 뒤바뀜이 나타나는가? 나타난다면 어떤 워크로드 매개변수(경쟁 수준, 중첩 깊이, 순서 위반 확률, 롤백 비용)에서 바뀌는가? 정확 오라클 대비 불필요한 제한 비율로 보면 처리량 중심 결과와 같은 방향인가?

하위 질문:

- Q3-1 (3a, 3d1) 정책 사이의 순위가 워크로드에 따라 뒤바뀌는가, 그 방향은 데이터베이스 문헌과 같은가?
- Q3-2 (3b) 정확 오라클 대비 불필요한 제한 비율(지표 M1)은 정책마다 얼마인가? (소규모 층에 한정)
- Q3-3 (3c) 요청당 비용(중앙값, p99), 정책 상태의 메모리, 롤백·재시도 분포, 대기 시간 꼬리, 기아 지표는 같은 하네스에서 함께 보고하면 어떻게 나뉘는가?
- Q3-4 (3d2) 지배 관계를 사전에 정의해 다지표로 분석하면 정책의 프런티어는 어떻게 생기는가? 퇴화하는가?
- Q3-5 (3g, RQ4에서 이월) 증분 위상 순서 승인(P-INC)의 요청당 비용과 거부율은 같은 트레이스에서 다른 정책과 비교하면 어떤가? 거부 뒤 경로(실패 처리, 트라이락 우회)를 정책에 넣으면 무엇이 달라지는가?

## 2. 주장하지 않는 것

- 새 설계점을 찾았다는 서술. 순위가 워크로드에 따라 뒤바뀐다는 관찰은 데이터베이스 2PL 비교(문헌 M78–M80, M82)에서 이웃 설정으로 이미 있다. 이 RQ에서 그 관찰이 나오면 이웃 설정의 재현이라고 쓴다.
- 혼합 정책(P-MIX)이라는 개념(3e)은 새롭지 않다(F11). 정책 목록의 한 항목일 뿐이다.
- P-INC가 새롭다는 서술. 증분 위상 순서 자료구조와 락 순서 검사에의 사용은 이미 구현되어 있다(S27, S28). 측정 항목일 뿐이다.
- 지표 M1이 제조 시스템·이산사건 시스템 문헌의 허용도(permissiveness, 문헌 M94, M95)와 같다는 서술. 방향은 같으나 단위가 다르다. 인용할 때 어느 쪽인지 적고 대응 표를 만든다(§6).
- 합성 워크로드의 결과를 실제 커널·응용에 일반화하는 서술.

### 4.2 정책 응답 의미

| 결정 | 뜻 | 스레드의 반응 |
|---|---|---|
| GRANT | 즉시 허가 | 진행 |
| WAIT | 락이 쥐어져 있어 기다림, 또는 정책이 지연시킴 | 막힘. 해제 사건 때 정책이 다시 평가 |
| DENY | 이 요청을 허가하지 않음 | 보유 락을 모두 반납하고 지수 백오프 뒤 같은 순서로 작업을 다시 시작. 재시도 상한 R_max 초과 시 작업 실패. 재시도해도 같은 결과가 나올 결정적 거부(P-ORD의 순서 위반)는 재시도 없이 바로 실패 |
| ABORT-OTHER | 다른 보유자를 중단(wound) | 피해자는 DENY와 같은 반응. 타임스탬프는 재시작해도 유지 |
| 희생자 선택(B1) | 교착 탐지 시 한 작업을 중단 | 피해자는 DENY와 같은 반응 |

R_max와 백오프 매개변수는 계획용 값이며 파일럿 뒤에 정한다(O3-5). 작업 실패율은 지표 M9로 보고한다.

### 4.3 P-INC의 거부 뒤 경로 (G5 결정 제안, 사람 확정 전)

문서 05 §2.5가 G5로 넘긴 결정이다. 제안: 두 변형을 모두 정책 목록에 둔다.

- P-INC-F: 순환을 닫는 요청을 거부하고 실패를 반환한다(DENY).
- P-INC-R: 순환을 닫는 요청만 대기하지 않는 경로(트라이락, 실패하면 보유 락을 모두 반납하고 백오프 재시도)로 처리한다. 순환을 닫지 않는 요청은 보통대로 대기한다.

wound나 wait-die로의 우회는 이 RQ에서 하지 않는다(독립 질문 RQ4의 WP4.4 범위였고 흡수로 폐기). P-INC-R이 교착을 만들지 않는다는 성질은 가정하지 않고 SP-5의 소규모 전수 검사로 확인한다. 의존 간선은 만료되지 않는다(lockdep처럼 누적. 만료 정책은 이 RQ의 범위 밖). 알고리즘은 세 가지다: A1 단순 DFS(기준), A2 Pearce–Kelly(본 구현), A3 단방향 탐색(마이크로벤치 전용). A1과 A2는 모든 요청열에서 거부 결정이 같아야 하며 차등 테스트로 확인한다. 이 결정은 CP2(RQ4 흡수의 확정)와 함께 사람이 확정한다.

### 4.4 워크로드

| 층 | 내용 | 상태 |
|---|---|---|
| L1 합성 | 아래 매개변수 격자 | 동결 대상 |
| L2 고전 문제 | 식사하는 철학자, 계좌 이체(락 2개) | 동결 대상 |
| L3 사용자 공간 트레이스 | 대상 응용은 SI-3에서 고른다(후보: 문헌 S6의 평가 대상) | 열린 항목 O3-2 |
| L4 커널 트레이스 | Linux VM이 있을 때만(선택) | 열린 항목 O3-3 |
| L5 사례 기반 | RQ5의 락 순서 패턴을 합성 템플릿으로 추상화(E2 표 복제 없음) | RQ5 코딩 뒤 |

생성기와 점검 결과는 `docs/rq3/workloads.md`(L1, L2)와 `traces/FORMAT.md`(트레이스 형식)에 있다.

L1 매개변수(계획용): 스레드 수 T = 16, 락 클래스 수 R = 32(중심값). 경쟁 수준은 락 선택 치우침(Zipf 지수)의 값으로 정의한다: 낮음 s = 0, 중간 s = 0.8, 높음 s = 1.2. 정책별로 실제 충돌 비율(요청이 이미 쥐어진 락을 만난 비율)을 결과로 함께 보고해 이 라벨이 타당한지 점검한다. 중첩 깊이 d ∈ {1, 2, 4}. 순서 위반 확률 p_v ∈ {0, 0.05, 0.25}(작업의 락 획득 순서가 전역 클래스 순서와 어긋날 확률). 롤백 비용 계수 ρ_rb ∈ {1, 10}(중단 시 잃는 작업량의 배율). 임계구역 길이 분포는 지수와 로그정규. 핵심 격자 = 경쟁(3) × 중첩(3) × 순서 위반(3) = 27셀을 T = 16, R = 32, 지수 분포, ρ_rb = 1에서 전수 실행한다. T, R, 분포, ρ_rb는 중심 셀(중간 경쟁, d = 2, p_v = 0.05) 주변의 일차원 스윕으로 본다. 소규모 층(§5의 M1)은 같은 구조를 T = 4, 작업당 락 사건 6개 이하의 크기로 줄인다.

## 5. 지표와 계산식

작을수록 좋은 방향으로 정의한다. 코드 M1–M8은 문서 02 §5.2를 따르고 M9는 더했다.

| 코드 | 지표 | 계산 |
|---|---|---|
| M1 | 불필요한 제한 비율(소규모 층만) | 아래 정의 |
| M2 | 교착 발생 | 예방·회피 정책은 0이어야 한다(SP-5의 관문). B0, B1은 작업당 교착 빈도 |
| M3 | 요청당 결정 비용 | 정책 코드의 벽시계 시간(ns). 중앙값과 p99. 비용 측정 모드(아래)에서 잰다 |
| M4 | 정책 상태 메모리 | 자료구조 크기의 분석적 계산과 최대 힙 사용량 측정 |

| M9 | 작업 실패율 | 실패한 작업 / 전체 작업. 1%를 넘으면 그 셀에서 그 정책은 '적용 불가'로 표시한다(계획용 값) |

**M1의 정의(초안, WP3.1에서 SI-2의 O2와 함께 확정하고 사람이 검토).** 오라클은 작업이 분기 없는 락 획득·해제 열이라고 가정하고 전체 프로그램을 안다(정책은 모른다). 상태 s에서 작업 t의 요청이 **오라클 허용 가능**하다는 것은 다음과 같다: 락이 비어 있으면 허가한 뒤의 상태가, 쥐어져 있으면 t가 기다리게 된 상태가 안전하다(모든 스레드가 끝나는 스케줄이 있다. 모델 명세 §3.5, O2). 정책의 결정이 DENY, 자기 중단, 다른 작업 중단(wound), 또는 락이 비어 있는데 허가하지 않는 지연이면 그 요청이 **제한됐다**고 센다. M1 = 제한된 오라클 허용 가능 요청 수 / 오라클 허용 가능 요청 수이며, 인스턴스별로 구한 뒤 인스턴스 위에서 부트스트랩한다. B0의 M1은 0이다(교착은 M2가 센다). B1이 교착을 푼 뒤 희생자를 중단하는 것은 교착을 만든 요청이 오라클 허용 가능하지 않으므로 M1에 세지 않는다. 안전성 판정이 일반적으로 NP-완전이므로(문헌 M9) 오라클은 소규모에 한정하고 크기 한계표를 SI-2에 둔다. 오라클 O2는 `oracle/locks.py`에 구현되어 있다(자체 검증: `formal/rq3/o2-check-results.md`). 아직 없는 것: 정책 실행에 M1을 적용하는 코드(제한된 요청 세기)와 O2의 크기 한계표. 큰 규모에서는 M1을 보고하지 않는다. 대신 '정책이 제한한 요청 비율'(오라클 없는 기술 통계)을 보고하며 M1이라 부르지 않는다.

**측정 모드.**

- 모드 S(시뮬레이션): 이산 사건 시뮬레이션, 논리 시간, 시드로 결정적. M1, M2, M5–M9.
- 모드 C(비용): 기준 실행에서 기록한 요청·해제 사건열을 정책 코드에 재생해 M3, M4를 잰다. 정책의 결정과 무관하게 기록된 사건을 따라 재생하고 정책 상태는 기록된 사건으로 갱신한다(결정 비용 측정 전용). SP-1의 다단계 반복 설계(P2)와 설정 무작위화(P4).
- 모드 R(실제 스레드, 선택): 다코어 Linux에서 방향을 확인한다. 작업공간(코어 2개)에서는 하지 않고 머리 주장에 쓰지 않는다(열린 항목 O3-3).
- 민감도 분석(탐색적): 모드 C의 M3 값을 임계구역 길이와 합치려면 변환 계수가 필요하다. 변환 계수 세 값(결정 비용 대 임계구역 길이 비 1:1, 1:10, 1:100)에서 '비용 포함 완료 시간'을 따로 보고하고 머리 주장에는 쓰지 않는다.

## 6. 문헌과의 대응표

- **교차 확인 표(`prereg/RQ3-crosscheck.md`, 사람이 원문으로 확인한 뒤 동결).** 문헌 M78–M81이 보고한 정책 쌍의 순위 방향(경쟁 낮음과 높음에서)을 원문에서 옮겨 적는다. 현재 이 방향을 열람 도구의 요약 수준(A−, B)으로만 보았으므로, 표가 동결되기 전에는 '방향 일치'를 판정하지 않는다. 비교하는 것은 수치가 아니라 방향(부호)이다.
- **허용도 대응표.** 지표 M1(트레이스 위의 요청 단위)과 문헌 M94, M95의 허용도(도달 가능한 안전 상태의 범위)의 정의와 단위를 나란히 적는다.
- 문헌 M47, M22(M30), M89, Bak 1976, Lomet 1977의 본문을 확인하기 전에는 3a, 3b에서 'OS 락 수준의 비교나 오라클 기준 측정을 찾지 못했다'를 '없다'로 쓰지 않는다(문서 05 §5.5의 7항).

## 7. 통계 절차와 판정 규칙

`prereg/README.md` §4를 따른다. 정책을 같은 시드의 같은 인스턴스로 짝짓고(SP-1), 시드 위의 백분위 부트스트랩을 쓰며(SP-2), 비율 A/B의 기하평균과 구간으로 비교한다(SP-3). δ = 0.05(계획용). 모드 S의 시드 수는 파일럿에서 '중심 셀의 보정한 95% 구간 반폭(로그 비율)이 δ의 절반 이하'가 되도록 정하며 하한은 200이다(계획용). 정한 시드 수는 본 실행 전에 커밋한다.

**머리 주장 가족(SP-4). 크기 k는 동결 때 적는다.**

- F1 순위 뒤바뀜: 교차 확인 표의 정책 쌍 × 지표 M5 × {낮은 경쟁, 높은 경쟁} (중심 중첩·위반에서).
- F2 지배: 핵심 격자의 셀마다 (적용 가능한 정책 쌍) × 주 지표. 소규모 층의 셀은 주 지표가 {M1, M3 중앙값, M5}이고 대규모 층의 셀은 M1이 없으므로 {M3 중앙값, M5}다. 셀 안의 가족으로 보정한다.
- F3 P-INC: P-INC-F, P-INC-R 각각을 P-ORD, P-WD, B1과 비교(주 지표 {M1(소규모), M3 중앙값, M5}) × {낮음, 중심, 높은 경쟁}.
- F4 M1과 M5의 방향 일치: 정책 쌍 × 소규모 셀에서 두 지표의 우열 부호(보정한 구간이 0과 구별되는 쌍만)가 같은 비율과 정확(Clopper–Pearson) 구간을 보고한다. 같은 정책이 여러 쌍에 들어가 쌍들이 독립이 아니므로 구간은 근사이고 기술 통계로만 쓴다. 구간 상한이 0.5 미만이면 P3-b를 반증하는 관측으로 적고, 하한이 0.5 초과이면 '대체로 같은 방향', 그 밖은 미결정.

그 밖의 비교(보조 지표 M4, M6–M9, 꼬리 지표 {M3 p99, M6 p99, M8}의 지배, 일차원 스윕)는 탐색적이다.

**판정.**

- 순위 뒤바뀜(쌍 단위): 낮은 경쟁과 높은 경쟁에서 log(M5_X/M5_Y)의 보정한 구간이 서로 반대편(0을 기준으로)에 있으면 '뒤바뀜 관측', 같은 편이거나 0을 걸치면 '관측 안 됨(또는 미결정)'. 교차 확인 표가 동결된 뒤에는 '문헌과 같은 방향', '다른 방향', '비교 불가(모델 차이)'를 덧붙인다.
- 지배(셀 단위): SP-3의 정의. 가르지 못한 쌍은 '미결정'으로 둔다. 프런티어 = 어느 정책에도 지배되지 않는 정책의 집합(미결정 쌍은 지배로 세지 않는다).
- 퇴화: 한 정책이 모든 셀에서 다른 모든 적용 가능 정책을 지배하면 프런티어가 퇴화한 것이다. 결과로 보고하고 종료한다.
- 구현 관문(SP-5)과 적용 불가(M9 > 1%)를 통과하지 못한 정책-셀은 프런티어 분석에서 빼고 사유와 함께 보고한다.
- 재현 전환 규칙: 문서 02 §5.2의 '동일한 비교 연구가 발견되면 재현 연구로 전환'은 3d1에 대해서만 발동한다(문서 05 §5.5). 그래서 Q3-1은 이웃 설정의 재현으로 쓰고 나머지 하위 질문은 측정으로 쓴다.

## 8. 허용되는 사후 변경

허용(기록하고 본 결과가 있는지 표시): 파일럿 뒤 격자·시드 수·R_max·백오프의 조정(본 실행 전), 구현 결함의 수정과 영향받는 실행 전체의 재실행, 입력군·정책의 추가(탐색적 표시), 크기 한계표의 조정.

## 10. 한계

- 오라클이 소규모에 한정되므로 M1은 소규모 층에서만 정확하다. 큰 규모의 결과는 M1 없이 해석한다.
- 합성 워크로드의 대표성은 L2, L3, L5와 비교해서만 가늠할 수 있고 L3, L4는 환경에 달려 있다.
- 시뮬레이션의 논리 시간은 정책 결정 비용을 포함하지 않는다(모드 C가 따로 재고, 합치는 것은 민감도 분석).
- 데이터베이스 문헌과의 대응은 근사이며 같다고 단정하지 않는다. 문헌 M78–M81의 방향은 원문 확인 전이다.
- 정방향 인용 추적을 하지 못했다(문서 05 §5.6). 같은 비교 연구가 있을 가능성이 이번 검색 밖에 남아 있다.
- 커널 문맥(스핀락, 인터럽트 문맥)에서 그래프를 갱신하는 비용과 동기화는 분석 항목이며 이 RQ에서 측정하지 않는다(미검증).
