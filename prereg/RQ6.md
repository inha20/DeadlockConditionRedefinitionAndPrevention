## 1. 질문

선별한 뱅커 계열 개선 주장(복잡도, 성능, 활용도, 정확성)은 같은 모델 가정, 같은 정확 오라클, 같은 입력과 같은 통계 절차에서 어떤 범주로 판정되는가?

범주는 유지 / 조건부 유지 / 불유지 / 비교 불가 / 재구현 불가이고(문서 02 §5.1) 어느 범주든 결과로 보고한다. 하위 질문:

- Q6-1 (6a) 문헌의 비용 표기를 하나의 기준(입력 크기 변수, 연산 단위, 사례 범주)으로 환산하면 표기는 어디에서 어긋나는가?
- Q6-2 (6b) 변형 구현의 안전·불안전 판정과 요청 허용·거부는 교재식 기준 구현과 정확 오라클에 얼마나 일치하는가? 불일치는 보수적인가 비보수적인가?
- Q6-3 (6c) 같은 하니스와 입력군에서 기준 대비 변형의 비용(비교 횟수와 시간)은 저자의 복잡도·개선 폭 주장과 어떻게 대응하는가?
- Q6-4 (6d) 모호한 의사코드를 해석별로 구현하면 판정과 비용은 해석에 따라 얼마나 달라지는가?
- Q6-5 (6e, 6f) 주장마다 어느 범주인가, 그리고 모델 가정의 차이 때문에 비교할 수 없는 주장은 어느 가정이 다른가?

## 2. 주장하지 않는 것

- 새롭다는 서술, '독립 재현이 없다'는 서술을 쓰지 않는다. 쓸 수 있는 말은 '이번 검색에서 독립적인 동일 조건 재현·비교를 찾지 못했고, 이웃 분야에는 정책 비교와 재평가의 선례가 있다'이다(문서 05 §7.5의 2항). 기여는 대상(교재식 모델의 뱅커 변형들)과 정확 오라클 대비 판정에 한정한다. 방법은 선례를 따른다(M126, M129, M13).
- 6g(개별 주장의 독립 검증)는 이 RQ의 기여가 아니다. 재현·반박 결과는 판정표의 칸으로만 쓴다.
- 범주별 기대 비율을 적지 않는다. 어떤 주장이 유지될 것이라는 예측도 적지 않는다(문서 05 §7.5의 1항).
- 불일치를 곧바로 오류로 단정하지 않는다. 모델 가정의 차이를 먼저 확인한다(문서 02 §5.1의 태도).

## 3. 검토할 명제와 반증 조건

가설 문구 대신 주장 유형별 반증 조건을 둔다. 주장마다 '무엇이 그 주장을 반박하는가'를 측정 전에 정한다.

| 유형 | 주장의 예(인벤토리) | 반박하는 관측 |
|---|---|---|
| 정확성 | 안전 상태 판정이 기준과 같다 | 오라클이 불안전으로 판정한 상태를 변형이 안전으로 판정한 입력이 하나라도 있다(FS > 0). 반례를 첨부한다 |
| 복잡도 | 평균·최악 O(f(n, m)), 조건부 상각 한계 | 저자가 정한 사례 범주와 입력에서 추정 지수의 신뢰구간 하한이 주장 지수 + ε보다 크다 |
| 성능 | 평균 시간 약 9% 개선 등 | 저자가 정한 조건에서 변형/기준 시간 비율의 구간이 1 이상이다 |
| 활용도·처리량 | 자원 활용도 개선 | 문헌이 활용도 정의와 워크로드를 충분히 쓴 경우에 한해 시도하며, 그 정의 아래 개선이 없다 |
| 모델 | 어느 유형이든 | 주장의 모델 가정이 기준 모델로 옮겨지지 않으면 '비교 불가'다. 이것은 반박이 아니라 비교의 성립 여부다(§7) |

## 4. 데이터·입력·제외 기준

**기준 모델과 오라클.** 교재식 다중 종류 뱅커(안전성 알고리즘과 자원 요청 알고리즘)를 `docs/rq6/reference.md`와 `bench/policies/banker/`에 정의한다(WP6.2). EWD623(F8)은 한 종류의 교환 가능한 자원의 판이므로 다중 종류의 기준을 따로 정의하고, 단일 종류에서는 F8의 동치(불안전 ⇔ 두 집단 분할 조건)를 오라클의 독립 교차 검증에 쓴다(원문 재확인 뒤). 정확 오라클은 모델 명세 §3.5의 O1(안전 ⇔ s_max 상태에 교착 없음)이며 작은 입력에서는 순열 전수 탐색으로 교차 검증한다.

**대상 주장의 선정.** 인벤토리(`refs/rq6-inventory.md`)에서 다음을 모두 만족하는 주장을 넣는다.

1. 뱅커 계열의 복잡도·성능·활용도·정확성 개선 주장이다.
2. 소프트웨어 알고리즘이다.
3. 의사코드 수준의 재구현이 가능한 설명을 본문에서 확인했다(초록이나 서지만 본 것은 해당 없음).
4. 모델이 교재식 다중 종류 뱅커이거나 문서에 적은 변환으로 옮겨진다.

넣지 않은 주장은 조용히 빼지 않고 최종 보고에 '분리, 비교 불가, 보류, 제외' 표로 사유와 함께 올린다. 현재 1–3을 충족하는 주장은 R6-05, R6-06, R6-07의 세 건이고, R6-04는 단계가 서술되어 있으나 모호해 해석별 구현이 필요하다(인벤토리 §8의 B-5 갱신). 네 건 모두 구현하고 문헌 예제를 재현했다(`docs/rq6/variants.md`). 단 R6-05와 R6-07(`dbdaa-cycle1` 읽기)은 판정 함수가 같아 판정 정확도에 관해서는 독립 증거가 아니고(`docs/rq6/variants.md` §4), R6-06은 도착이 없으면 교재식 Sweep과 계측 계수가 같다. R6-06은 시험할 정량 주장이 없고 R6-04의 '약 9%'는 조건이 없어 시험할 수 없다. 이런 경우의 범주는 열린 항목 O6-9다. 하드웨어 전용 주장(R6-03)은 소프트웨어로 재현할 수 없으므로 구조 수준 비교만 시도하고 범주는 '비교 불가'다. 본문을 읽기 전에는 어느 주장도 범주를 정하지 않는다.

**주장 단위 부록(`prereg/RQ6-claims.md`, 이 파일이 동결된 뒤 WP6.3 전에 작성).** 주장마다 한 행으로 다음을 적고, 측정 전에 커밋해 타임스탬프를 남긴다: 주장 ID(`C-RQ6-NNN`), 출처와 쪽, 주장 유형, 저자가 적은 조건(사례 범주 평균·최악·상각, 입력 분포, 모델 가정), 저자가 적은 수량(지수, 개선 폭), 해석 목록과 대표 해석(문헌 예제를 재현하는 해석 가운데 저자의 서술에 가장 가까운 것)과 선택 이유, 주 지표와 입력군, 범주 경계의 구체값(§7의 ε, δ_r). 이 부록의 주 지표가 머리 주장의 가족이다.

**입력군.**

- F-ex 소규모 전수. 범위는 SI-2의 크기 한계표를 따른다(제안: 프로세스 4개 이하, 자원 종류 3개 이하, 총량 3 이하. 기존 SM 전수 범위와 같은 규모).
- F-rand 무작위. 총량 벡터, 최대 청구 행렬, 보유 행렬을 보유 ≤ 최대 ≤ 총량과 종류별 보유 합 ≤ 총량을 만족하도록 생성한다. 안전 상태 비율 목표를 0.1, 0.5, 0.9로 두고 오라클로 거절 표집한다(안전이면 일찍 끝나는 경로가 다르므로 비용이 입력의 안전성에 의존하기 때문이다). 생성기와 시드를 공개한다.
- F-bound 경계·적대적. (i) 교재식의 최악 입력: 안전 순서가 스캔 순서의 역이라 바깥 반복이 n번 필요한 입력, (ii) 변형마다 의사코드에서 만든 적대적 입력(주장 단위 부록에 기록), (iii) 경계: 필요량 = 가용량, 영행·영열, 프로세스 1개, 종류 1개.
- F-lit 문헌 예제. 각 논문의 예제 입력을 그대로 넣는다. 현재 `bench/literature/`에 DBDAA(표 2–4), Begum 외(표 I–II), Wicaksono 외(표 1–5), Dixit·Khuteta(표 3–5), Botlagunta 외(표 1·3·5)의 예제가 있다. 구현의 출력이 논문이 보고한 출력과 맞는지(문헌 예제의 재현)는 동결 전에 확인했다. 이것은 K1–K3의 측정이 아니다. 예제의 입력이 내부적으로 모순이면 '예제 재현 불가(입력 모순)'로 기록하고 저자 문의 대상에 올린다. 알고리즘의 오류로 단정하지 않는다(문서 05 §7.5의 5항).

**크기 격자(계획용, 파일럿의 실행 시간으로 상한을 조정).** n = 16–4096(2배씩), m = 2–256(2배씩). 일차원 스윕 둘(m = 8 고정에서 n 변화, n = 256 고정에서 m 변화)과 대각선(n, m 동시 증가) 하나. 점마다 시드 수는 SP-1이 정하고 하한은 30이다(계획용).

**제외 기준.** 생성기가 거부한 입력(전제 위반)은 수를 세어 보고한다. 측정 중 환경 오류로 중단된 실행은 사유와 함께 세고 같은 시드로 다시 실행한다. 결과가 나쁘다는 이유의 제외는 허용하지 않는다.

## 5. 지표와 계산식

| 코드 | 지표 | 정의 |
|---|---|---|
| K1 | 판정 일치 | 입력 상태마다 변형의 안전·불안전 판정과 요청 허용·거부를 오라클과 대조한다. 거짓 불안전 FU(오라클 안전, 변형 불안전. 보수적)와 거짓 안전 FS(오라클 불안전, 변형 안전. 비보수적)를 따로 센다. 전수에서는 정확한 개수, 표본에서는 비율과 Clopper–Pearson 정확 구간 |
| K2 | 비교 횟수 | 안전 검사 한 번당 스칼라 비교 횟수(기본 단위, 문서 04 §2.2의 제안)와 벡터 비교 횟수를 따로 센다. 계측 코드가 시간에 영향을 주지 않도록 횟수를 세는 실행과 시간을 재는 실행을 분리한다. 보조 수량으로 반복 방문 수도 기록한다(탐색적. 제안, O6-7) |
| K3 | 시간 | 안전 검사 한 번당 벽시계 시간과 CPU 시간. 타이머 분해능 오차를 줄이려고 안쪽 반복을 둔다(SP-1) |
| K4 | 추정 지수 | 크기 격자의 점별 요약값(중앙값)에 대한 로그–로그 회귀의 기울기 α_n, α_m. 구간은 점 안에서 인스턴스를 재표집해 요약값과 기울기를 다시 계산하는 부트스트랩으로 구한다(SP-2) |
| K5 | 개선 비율 | ρ = 변형/기준의 시드별 비율 기하평균(K2 또는 K3에 대해). 비율은 같은 인스턴스끼리 짝짓는다 |
| K6 | 해석 민감도 | 같은 주장의 해석들 사이에서 K1, K4, K5의 최대–최소 폭, 해석별 범주 |

주 지표(머리 주장)는 주장 단위 부록에서 주장마다 K1, K4, K5 가운데 그 주장의 반박 조건에 해당하는 것을 정한다. 나머지는 보고하되 탐색적이다.

## 6. 통계 절차

`prereg/README.md` §4를 따른다. 시드별 짝지은 비교(SP-1), 시드 위의 백분위 부트스트랩(SP-2), 머리 주장 가족의 구간 수준 보정(SP-4. 가족 = 주장 단위 부록의 주 지표 전체, 크기 k는 부록 동결 때 적는다). 작업공간은 코어 2개를 공유하는 가상 환경이므로 절대 시간은 주장하지 않고 비율과 기울기만 주장한다. 비교 횟수는 환경에 의존하지 않으므로 복잡도 주장의 1차 근거는 K2이고 K3은 보조다. 복잡도 주장은 K2와 K3이 같은 방향인지도 함께 보고한다.

## 7. 판정 규칙

범주 경계의 구체값 ε(지수 허용 오차)와 δ_r(개선 폭 허용 오차)은 계획용 제안이며 동결 때 정한다: ε = 0.15, δ_r = 0.05. 유한한 크기 범위에서 점근 지수는 흐려지므로 허용 오차가 필요하다.

**비교 불가(측정 전에 판정).** 모델 가정 점검표를 주장마다 채운다: 요구 정보(최대 청구)의 사전 공개 여부, 자원 종류·단위 수, 프로세스 구조(고정 집합인가 도착·이탈이 있는가), 실행 중 자원·프로세스 변화, 시간 지식, 하드웨어 구현, 분산. 기준 모델과 다른 칸이 문서에 적은 변환으로 옮겨지지 않으면 비교 불가다. 점검표는 AI가 채우고 사람이 확인하며 의견이 다르면 둘 다 적고 최종은 사람이 정한다. 비교 불가 주장도 결과로 보고하고 어느 칸이 다른지 6f의 표에 올린다.

**재구현 불가.** 가능한 해석을 모두 구현했는데 문헌 예제를 재현하는 해석이 하나도 없고 저자 문의가 해소되지 않았을 때다. 입력의 모순으로 예제가 재현되지 않는 경우는 이 범주가 아니라 '예제 재현 불가(입력 모순)' 표시이며, 의사코드로 판정할 수 있으면 계속한다.

**유형별 범주.** 비교 불가·재구현 불가가 아닌 주장에 대해:

| 유형 | 유지 | 조건부 유지 | 불유지 |
|---|---|---|---|
| 정확성 | F-ex, F-rand, F-bound, F-lit 모두에서 FU = FS = 0 | FS = 0이고 FU > 0인데 저자가 보수적 판정을 명시했거나, 불일치가 저자가 정한 가정 밖의 입력에서만 생김. FU의 비율을 함께 보고 | FS > 0(반례 첨부), 또는 저자가 정확하다고 썼는데 FU > 0 |
| 복잡도 | 주장 사례 범주에서 α의 95% 구간 상한이 주장 지수 + ε 이하 | 일부 조건(사례 범주, 입력군, 비교 횟수에만)에서만 성립. 최악 사례 주장인데 주장 한계의 성장률과 맞는 최악 입력 계열을 구성하지 못함(최악 입력을 구성하지 못한 채 '유지'라고 쓰지 않는다) | α의 구간 하한이 주장 지수 + ε보다 큼 |
| 성능 | ρ의 구간 상한이 주장 비율 + δ_r 이하 | ρ의 구간이 1 미만이나 주장 비율 + δ_r을 넘음, 또는 일부 입력군에서만 | ρ의 구간이 1 이상(개선 없음 또는 악화) |
| 활용도 | 문헌의 정의와 워크로드로 개선이 재현됨 | 일부 조건에서만 | 재현되지 않음. 정의나 워크로드를 쓰지 않은 주장은 비교 불가 |

**보류.** 측정 범위(크기 격자)에서 구간이 위 경계를 가로질러 어느 쪽도 가르지 못하면 격자를 한 번 넓힌다(§8). 그래도 가르지 못하면 다섯 범주 어디에도 세지 않고 '보류(사유)'로 판정표에 올린다. 보류는 범주가 아니라 상태이며, 이 구분의 승인은 열린 항목이다.

**해석 민감도.** 최종 범주는 대표 해석의 범주다. 다른 해석에서 범주가 다르면 해석별 범주를 병기하고 K6을 보고한다.

**중단·축소 규칙(문서 02 §5.1).** (1) 재구현 가능한 주장의 수가 N_min(§9)에 못 미치면 인벤토리 범위를 넓히거나 재현 없이 문헌 비교로 줄인다. (2) 모든 주장이 비교 불가이면 문헌 간 모델 가정 불일치 지도(6f)를 결과로 삼고 끝낸다. (3) 기준 구현이 오라클과 어긋나면(SP-5) 다른 모든 작업에 앞서 고친다.

배지 분류(P1): 각 재현 결과를 저자의 아티팩트를 썼는지로 Reproduced(사용)와 Replicated(미사용)로 나눈다. 코드를 공개한 변형 논문은 아직 확인하지 못했다.

## 8. 허용되는 사후 변경

허용(기록하고 이미 본 결과가 있는지 표시): 크기 격자의 확대나 축소(실행 시간 때문. 판정이 가르지 못하는 주장에 한해 한 번 확대), 입력군 추가(탐색적 표시), 생성기·구현 결함의 수정과 영향받는 실행 전체의 재실행, 저자 문의 결과에 따른 해석 추가·범주 변경, 오타·표기 수정.

허용하지 않음: 결과를 본 뒤 주 지표나 범주 경계(ε, δ_r)를 바꾸는 것, 측정한 주장을 판정표에서 빼는 것(중단하면 '중단(사유)'로 남긴다), 범주의 정의를 바꾸는 것, 불리한 입력군을 제외하는 것.

## 10. 한계

- 대상 주장 후보의 본문 확인이 부족하다. 의사코드를 본문에서 확인한 소프트웨어 주장이 3건(R6-05, R6-06, R6-07)이고 모호한 1건(R6-04)이 있으며 나머지는 초록·서지 수준이다(인벤토리 §8). R6-05와 R6-07은 사용자가 제공한 PDF를 읽어 기계로 대조했고, R6-06은 저널 사이트 PDF를, R6-04는 제3자 사본을 열람 도구가 읽은 텍스트로 읽었다(PDF 대조 전). 이 파일의 범주 규칙은 본문을 읽은 뒤 주장 단위 부록에서 구체화된다.
- 기준 알고리즘의 비용 표기가 문헌마다 다르다(Θ(mn²), O(n²d), O(n³d), O(n²×m)). 무엇을 센 값인지 본문 확인 전이며 오류로 단정하지 않는다(문서 04 §2.3). K2의 기본 단위를 스칼라 비교로 둔 것은 제안이다.
- 정방향 인용 추적을 하지 못했고(문서 05 §7.6) 영어·중국어 일부 외의 문헌은 검색하지 않았다. 이 때문에 선행 재현·비교 연구를 찾지 못했다는 서술은 이번 검색 범위 안의 서술이다.
- 작업공간의 시간 측정은 잡음이 있으므로 비율과 기울기만 주장한다.
