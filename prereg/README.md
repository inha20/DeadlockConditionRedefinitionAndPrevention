## 2. 동결 절차

1. 사람이 해당 파일과 문서 06의 열린 결정 목록을 검토한다. 고칠 곳은 고친다.
2. 파일의 '열린 항목'을 모두 채운다. 비어 있으면 동결하지 않는다.
3. 동결한다: 커밋하고 `prereg-RQx-v1` 태그를 단다. 문서 00에 검토자와 일자를 적는다. 검토 기록이 없으면 태그를 달지 않는다.
4. 동결 뒤의 변경은 각 파일의 '변경 기록'에 일자, 바꾼 것, 사유, 이미 본 결과가 있는지, 영향을 적는다. 결과를 본 뒤에 바꾼 것은 그렇게 표시한다.

동결 전에 허용되는 작업(문서 02 §3): 오라클·하네스 같은 측정 도구, 기존 알고리즘의 기준 구현과 문헌 변형의 재구현(문헌 예제를 재현하는 데까지), 정의·정리 초안(증명 완성은 제외), 파일럿(분산 추정, 코더 일치도). 허용되지 않는 작업: 계획이 정한 지표를 정한 입력군에서 재는 본 실행과 그 결과의 분석, 새 아이디어의 구현·증명 완성, '확정'이라는 서술.

파일럿 자료는 본 분석에 쓰지 않는다. 쓸 때에는 해당 파일에 사전에 적는다(RQ5의 파일럿 사례는 49건 안의 사례이므로 본 코딩에 포함된다고 RQ5.md에 적어 두었다).

## 4. 공통 통계·측정 규약

측정을 하는 RQ(RQ6, RQ3)가 따른다. RQ1, RQ5, RQ2는 필요한 부분만 인용한다. 숫자 가운데 '계획용'이라고 적은 것은 동결 때 사람이 정한다.

- **SP-1 반복과 무작위화.** 독립 단위는 시드로 만든 입력 인스턴스다. 정책을 비교할 때에는 같은 시드의 같은 인스턴스를 모든 정책에 준다(짝지은 비교). 실행 순서는 (정책 × 셀 × 시드) 전체에서 무작위로 섞고 시드는 기록한 마스터 시드에서 결정적으로 만든다. 벽시계 시간은 다단계 반복 설계를 따른다(P2). 파일럿에서 단계별 분산 성분을 구해 본 실행의 반복 수를 정하고, 목표 정밀도는 95% 신뢰구간 반폭이 중앙값의 5% 이내다(계획용). 파일럿 결과와 정한 반복 수는 본 실행 전에 커밋한다. 논리 시간(시뮬레이션)은 잡음이 없으므로 시드 수만 정한다. 실험 설정의 사소한 차이가 결론을 바꿀 수 있으므로(P4) 컴파일러와 옵션, OS, CPU 모델, 코어 수, 가상화 여부, 알 수 있는 주파수 정책을 실행마다 기록한다. 작업공간은 코어 2개를 공유하는 가상 환경이므로 절대 시간이 아니라 정책 사이의 상대 비율과 입력 크기에 따른 기울기만 주장한다.
- **SP-2 구간 추정.** 시드(독립 입력)를 단위로 한 백분위 부트스트랩을 쓴다. 지표마다 요약이 중앙값인지 기하평균인지 RQ 파일에 적는다. 정책 사이 비교는 시드별 비율(A/B)의 로그 평균을 되돌린 기하평균 비율과 같은 방법의 구간으로 한다. 재표집 수 B는 10,000 이상이며, 보정한 수준의 한쪽 꼬리에 재표본이 100개 이상 들어가도록(B ≥ 100/(꼬리 확률)) 늘린다. 인스턴스 안의 사건 비율(예: 요청 가운데 제한된 비율)은 인스턴스별 비율을 먼저 구한 뒤 인스턴스 위에서 부트스트랩한다.
- **SP-3 효과 크기와 지배.** 주 지표는 모두 작을수록 좋은 방향으로 정의한다(처리량은 완료 시간으로 대신한다). A가 B보다 '나쁘지 않다'는 짝지은 비율 A/B 구간의 상한이 1 + δ 이하라는 뜻이고 '유의하게 좋다'는 상한이 1 미만이라는 뜻이다. A가 B를 지배한다는 것은 주 지표 전부에서 나쁘지 않고 적어도 하나에서 유의하게 좋다는 뜻이다. δ = 0.05(계획용). 가르지 못하면 '미결정'으로 보고하고 순위를 억지로 매기지 않는다.
- **SP-4 다중 비교.** 머리 주장(RQ 파일이 '가족'으로 사전에 나열한 비교)은 가족 크기 k로 구간 수준을 1 − 0.05/k로 올려 판정한다(Bonferroni형). 가족에 없는 비교는 '탐색적'이라고 표시하고 보정 없는 95% 구간과 함께 보고한다. 탐색적 결과를 머리 주장으로 올리려면 새 자료로 확인하는 실험을 사전 등록으로 추가해야 한다.
- **SP-5 구현 무결성 관문.** 정책과 변형 구현은 다음을 통과하기 전에는 결과 분석에 쓰지 않는다: ① 소규모 전수 검사에서 교착 0(예방·회피 정책에 한함), ② 정확 오라클 또는 두 번째 독립 구현과의 차등 테스트 일치, ③ 속성 기반 테스트. 통과하지 못한 구현은 결과에서 조용히 빼지 않고 '구현 결함'으로 보고한 뒤 고쳐서 다시 실행한다(재실행은 변경 기록에 적는다).
- **SP-6 부정 결과와 원자료.** 반증, 비교 불가, 미결정도 같은 형식으로 보고한다. 원자료·시드·스크립트를 보존한다(`experiments/`). 제3자 자료는 링크와 해시만 둔다.
- **SP-7 주장 대장.** 보고서의 모든 결과 주장은 `refs/claims-ledger.md`에 `C-RQx-NNN`으로 올리고 확인 수준(자체 계산은 V)을 붙인다. 수준 C 이하는 논증의 전제로 쓰지 않는다.
- **SP-8 표현 규칙.** '새롭다', '처음이다', '독립 재현이 없다'를 쓰지 않는다. 부재는 '이번 검색에서 찾지 못했다'로 쓴다. AI가 쓴 초안은 그렇게 표시한다. 사람의 검토 전에는 'RQ 확정'이라고 쓰지 않는다.
