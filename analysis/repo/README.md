# 저장소 점검 도구 (AV-4)

`check_repo.py`는 저장소의 문서들이 서로 맞는지 읽기 전용으로 점검하고, 저장소의 자체 점검 17개를 한 번에 돌린다. 표준 라이브러리만 쓰는 Python 3 스크립트이며 커밋 해시와 태그를 보려고 `git`을 부른다. AI(Claude)가 쓴 초안이며 사람의 검토 전이다.

**이 점검이 보는 것은 문서의 형식과 일관성(경로, 절, 해시, 번호, 집계, 위생)이다. 문헌 내용이 옳은지, 칸의 상태나 판정이 맞는지는 보지 않는다. 증명도 검증도 아니다.**

## 실행

저장소 루트에서 돌린다.

```
python3 -I analysis/repo/check_repo.py                                      # 정적 점검과 자체 시험(약 15초)
python3 -I analysis/repo/check_repo.py --report formal/repo/repo-check.md   # 같은 내용을 보고서로 저장(처음에는 두 번)
python3 -I analysis/repo/check_repo.py --run --run-report formal/repo/run-all-check.md   # 모든 자체 점검(코어 2개에서 약 15분)
python3 -I analysis/repo/check_repo.py --run --quick                        # 오래 걸리는 점검을 뺀다
python3 -I analysis/repo/check_repo.py --run --only grid,workloads          # 이름으로 고른다
```

종료 코드는 오류가 있거나 자체 시험을 놓치면 1이다. '알림'은 사람에게 알릴 것이며 종료 코드를 바꾸지 않는다. 보고서를 처음 만들 때는 보고서 파일이 아직 없다는 오류가 보고서에 들어가므로 두 번 돌린다.

## 정적 점검: 규칙 13개

| 규칙 | 보는 것 | 종류 |
|---|---|---|
| 경로 | 문서의 `백틱` 경로, 코드 블록 안의 경로, 마크다운 링크가 가리키는 파일·폴더가 있는가. 아직 만들지 않은 산출물은 `PLANNED`에 이유와 함께 적는다 | 오류 |
| 절 참조 | `` `경로` §N.M ``과 `문서 NN §N.M`이 가리키는 절(번호가 붙은 제목 또는 굵은 소제목)이 있는가 | 오류 |
| 해시 | 7자리 커밋 해시가 이 저장소의 커밋인가(다른 저장소의 커밋은 `EXTERNAL_COMMITS`), 해시 자리에 `git log` 명령을 쓰라는 안내를 적지 않았는가 | 오류 |
| 대장 | 주장 대장의 행(8열, ID 중복·틈 없음, 수준 어휘, 낮은 수준이나 2차 경로는 전제로 사용 불가, 확인일 형식)과 문서가 인용한 대장 번호(범위 포함) | 오류 |
| 검색기록 | `G4-nnn`이 1부터 연속인가, 문서의 인용(범위 포함)이 있는 번호인가, `G4-nnn부터`가 다음 번호인가 | 오류 |
| 열린항목 | `O1-n`–`O6-n`이 `prereg/RQ?.md`에 정의되어 있고(범위·목록 표기 포함) 번호에 틈이 없는가 | 오류 |
| 문서07 | §3.1의 집계, '전체 행은 N개', '둘 이상(N행)', AI가 할 수 있는 일의 개수와 목록, BL·AV 참조, 다른 문서가 적은 '하지 못한 일 N건' | 오류 |
| 수치인용 | README·문서 07·대장이 적은 점검 개수가 각 보고서의 값과 같은가, 보고서가 실패를 적지 않았는가, 이 도구의 보고서가 낡지 않았는가 | 오류 |
| 현재상태 | README의 '현재 상태' 날짜가 진행 기록의 마지막 날짜보다 이르지 않은가, 문서에 적은 격자·prereg 버전이 문서 머리와 같은가 | 오류 |
| 구성 | README 구성 표에 최상위 폴더가 모두 있는가, `docs/`·`formal/`·`analysis/`의 하위 폴더를 README가 설명하는가 | 오류 |
| 주장수위 | 'G5 … 통과'를 단정한 문장이 없는가, 동결 태그(`spec-v1`, `prereg-RQ*-v1`)가 생기지 않았는가 | 알림 |
| 위생 | 추적하면 안 되는 형식(PDF, 압축 파일, 바이트코드), 50MB 초과, 비밀값처럼 보이는 문자열은 오류. 10MB 초과, 개인 경로(사용자 이름), 이메일 주소는 알림 | 오류·알림 |
| 러너 | 모든 `check_*.py`가 실행 목록(`CHECKS`)에 있고, 목록의 스크립트와 보고서 파일이 있는가, 문서가 적은 '자체 점검 N개'·'점검 규칙 N개'가 목록 길이와 같은가 | 오류 |

보고서에는 개인 경로나 이메일 주소의 값을 적지 않는다(파일과 줄 번호만).

## 자체 시험

일부러 망가뜨린 저장소 사본(메모리 안의 복사본)을 같은 점검에 넣어 규칙마다 새 문제가 나오는지 본다. 기준 문구는 정규식으로 찾아서 문서의 값이 바뀌어도 시험이 깨지지 않으며, 기준 문구가 사라지면 시험을 고치라는 메시지로 멈춘다. 종류 '정상'은 거꾸로, 올바른 표기(조사가 붙은 경로, 꺾쇠 자리표시, 범위 표기 등)를 더했을 때 오탐이 나지 않는지 본다. 하나라도 놓치면 종료 코드 1이다. 시험 목록은 `formal/repo/repo-check.md`의 표에 있고, 그 개수는 README와 문서 07이 적은 값과 같은지 점검 대상이다.

## 모든 자체 점검의 일괄 실행(`--run`)

`CHECKS`에 적은 자체 점검 17개를 `python3 -I -B`로 하나씩 돌린다(기본 병렬 2, 오래 걸리는 것을 먼저 시작한다). 각 점검의 보고서는 `--out`(기본: 임시 폴더. 절대 경로로 바꿔 쓴다)에 쓰고 저장소의 보고서는 건드리지 않는다. 실행 전후로 저장소의 모든 파일(무시한 파일 제외)의 내용 해시를 견줘 바뀐 파일이 있으면 알리고 종료 코드 1을 낸다. 코드북 도구와 격자 점검은 다시 만든 보고서가 저장소의 것과 바이트까지 같아야 통과한다. `--quick`은 `slow` 표시가 붙은 점검(RQ3 정책 전수 검사 약 11분, 뱅커 정책 차등 검사 약 2.7분)을 뺀다. 기록은 먼저 출력 폴더에 남긴 뒤 `--run-report`의 경로에 쓴다(긴 실행의 결과를 잃지 않으려고. `docs/00-progress-log.md`의 2026-11-02 '작업 사고 기록' 참고). 기록은 `formal/repo/run-all-check.md`에 있다.

## 목록을 고칠 때

| 목록 | 언제 |
|---|---|
| `PLANNED` | 문서가 아직 만들지 않은 산출물의 경로를 인용할 때. 산출물이 생기면 목록에서 뺀다(안 빼면 오류) |
| `EXTERNAL_COMMITS` | 다른 저장소의 커밋 해시를 인용할 때 |
| `CHECKS` | 자체 점검 스크립트를 더하거나 보고서 경로를 바꿀 때. 안 더하면 `러너`가 오류를 낸다 |
| `PAIRS`, `COUNT_DOCS` | 문서가 점검 개수를 적는 문장을 바꿀 때. 문장이 사라지면 '인용 문구를 찾지 못했다'는 오류가 난다 |
| `G5_NEG` | 'G5 … 통과'가 든 부정문의 표현을 새로 쓸 때 |

## 하지 않는 것

- 문서가 말하는 내용이 사실인지, 칸의 상태나 판정이 맞는지, 문서 07의 사유 분류가 맞는지는 보지 않는다. 숫자와 이름이 서로 맞는지만 본다.
- 경로는 전체 경로(`analysis/`, `bench/`, `docs/`, `experiments/`, `formal/`, `oracle/`, `prereg/`, `refs/`, `traces/`로 시작하거나 `README.md`)만 본다. 짧은 파일 이름은 보지 않는다. 경로의 글자는 ASCII뿐이라고 가정한다(이 저장소에는 한글 파일 이름이 없다).
- 7자리가 아닌 해시, 외부 문헌의 번호, 문장 사이의 모순은 보지 않는다.
- 정규식으로 문서를 읽으므로 서식이 크게 바뀌면 '찾지 못했다'는 오류가 날 수 있다. 오탐을 피하려고 일부러 느슨하게 둔 곳(`G5_NEG`)이 있어 그 규칙은 놓칠 수 있고, 그래서 오류가 아니라 알림만 낸다.
- 이 점검이 0건이라는 것은 형식과 일관성이 맞다는 뜻이며 연구가 옳다는 뜻이 아니다.
